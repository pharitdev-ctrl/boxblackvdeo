# Where each library built into @img/sharp-libvips-darwin-arm64's libvips-cpp.dylib comes from, so
# third-party-notices.mts can take its license text from the source archive of the exact version
# the package's versions.json lists. One line per versions.json key:
#
#   <versions.json key>  <its name(s) in the package's README.md table>  <source archive url>  [more license files]
#
# In the url, {v} is the version from versions.json, {v_} and {v-} the same with its dots as _ or
# -, and {vmm} its major.minor. The archives are the ones sharp-libvips' own build script
# (build/posix.sh at the package's release tag) fetches, or the same tag's source archive on
# GitHub. Every license file at an archive's top level (LICENSE*, COPYING*, COPYRIGHT*, NOTICE*,
# PATENTS*) is taken; the last column names more, relative to that top level: a file (only the
# opening comment of a .c or .h file), <folder>/* for the license files of every dependency
# vendored in its own folder there, or cargo-lock for a library partly written in Rust whose
# archive no longer vendors its crates: every crate its top-level Cargo.lock takes from crates.io
# then has its license files taken from that crate's own archive there, at the locked version.
# The pack build fails when versions.json or the README names a library no line here covers, or
# a line names one they do not -- update this list when a new sharp-libvips moves a library or
# adds one.
