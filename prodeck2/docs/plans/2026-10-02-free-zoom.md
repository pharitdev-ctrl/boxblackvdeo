# Free Zoom Implementation Plan (0.8.0)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Claude designs the picture's moves itself: free keyframes of scale, shift, rotation and ease, at any word, on the main footage and on cutaways. The app checks every move and writes it as keyframes. Highlight text and graphics then avoid the face where it is after the zoom. Release 0.8.0.

**Architecture:**
- **Data.** A "move" is a list of poses anchored on a spoken word (or on a cutaway).
- **Core geometry.** Pure core code samples a move's pose at any moment and checks it:
  - the cap from the video's resolution;
  - rotation;
  - edge cover;
  - the face inside the frame;
  - a shown thing's centre on screen.

  It also gives the face's box after the zoom.
- **Planning.** The techniques work asks Claude for moves and cutaways in one call, and now runs before the text.
- **Placement.** Main places the moves on pieces, cuts each at its piece's end, and feeds the zoomed face to the highlight placement and the graphics room.
- **Writing.** The writer turns the poses into CapCut keyframes (eases made of straight steps), on the main pieces and on cutaway overlays.
- **Legacy.** Legacy punch/drift zooms keep playing until thought again.

**Tech Stack:** TypeScript on Node 26, Electron 44, React, zod 4, vitest. There is no git: "commit" means `npm test` green and `npm run typecheck` clean from the repo root.

**Spec:** `docs/specs/2026-10-02-free-zoom-design.md` (Thai, approved 2026-10-02). **Spike:** `docs/plans/2026-10-02-zoom-spike/` (rotation, many keyframes, pan, eased steps and overlay keyframes all play; no Pro).

export const EASES = ["line", "in", "out", "inOut", "cut"] as const
export type Ease = (typeof EASES)[number]
/** A pose `s` seconds after the move's start: scale (1 = as is), shift in half-frames (CapCut's units), degrees, and how it is reached from the pose before. */
export interface Pose { s: number; scale: number; x: number; y: number; rot: number; ease: Ease }
export interface MoveCue {
  /** a spoken word (speech anchor), or a cutaway's start with `insert: true` */
  anchor: CueAnchor
  insert?: boolean
  from: FlairLevel
  pointId?: string
  /** Claude's one line in Thai on what the move does */
  about: string
  poses: Pose[]
  edited: boolean
  off: boolean
  instruction?: string
  editFailed?: string
  previous?: { poses: Pose[]; about: string; instruction?: string }
}
export const MOVE_POSES_MAX = 12
export const ROT_MAX = 5
export const SCALE_CAP_1080 = 1.3
export const SCALE_CAP_MAX = 1.5
/** Straight steps per eased segment when written for CapCut. */
export const EASE_STEPS = 8
export const isMove = (value: unknown): value is MoveCue

### Task 1: Core: move geometry

**Files:** Create `packages/core/src/flair/moves.ts`, `moves.test.ts`; export from `packages/core/package.json` (`./flair/moves`).

- [ ] **Step 1: types and constants.** Write them as above. `isMove` checks:
  - `anchor` is an object;
  - `from` is a level;
  - `about` is a string;
  - `poses` is a non-empty array of numeric poses with a known `ease`;
  - `edited` and `off` are booleans.

  Test both shapes that pass and shapes that fail.
- [ ] **Step 2: `poseAt(poses, s)`.** It gives the pose at `s` seconds:
  - **Before the first pose:** the first pose.
  - **After the last pose:** the last pose (held).
  - **Between poses `a` and `b`:** `b.ease` shapes the mix `t = (s - a.s) / (b.s - a.s)`:

    | Ease | Mix |
    |---|---|
    | `line` | `t` |
    | `in` | `t²` |
    | `out` | `1 - (1 - t)²` |
    | `inOut` | `t < .5 ? 2t² : 1 - (-2t + 2)² / 2` |
    | `cut` | `b` at once (`t = 1` for any `s > a.s`) |

  Test each ease at `t` = 0, 0.25, 0.5 and 1.
- [ ] **Step 3: `steps(poses)`.** It gives the straight-line keyframe points `{ s, scale, x, y, rot }[]` the writer uses:
  - **A `line` segment:** its end point only.
  - **An `in`, `out` or `inOut` segment:** `EASE_STEPS` points sampled with `poseAt`.
  - **A `cut` segment:** a point 1 ms after `a.s` at `b`, then `b` at `b.s`.

  The first point is the first pose. Test the counts and the values.
- [ ] **Step 4: `zoomCap(video: { width: number; height: number }, canvas: { width: number; height: number })`.**
  - `const fit = Math.max(canvas.width / video.width, canvas.height / video.height)` (how much CapCut already enlarges to cover).
  - The cap is `clamp(SCALE_CAP_1080 / fit × (shortSide(video) ≥ 2160 ? SCALE_CAP_MAX / SCALE_CAP_1080 : 1), 1, SCALE_CAP_MAX)`.

  In words: a 1080×1920 video on a 1080×1920 canvas gets 1.30, a 4K one gets 1.50, and a 720p one gets less than 1.30 (but at least 1). Test those three, and a landscape one.
- [ ] **Step 5: the frame geometry.**
  - **Frame.** The canvas is the square [−1, 1]² in CapCut units, corrected for aspect: `x` is in half-widths and `y` in half-heights.
  - **The picture at a pose:**
    - it is the frame scaled by `scale` about the centre;
    - then rotated by `rot` degrees, with the aspect respected: compute in pixels using `canvas.width/height`;
    - then shifted by `(x, y)` half-frames;
    - for a cutaway, the picture's base framing (from `framing.ts`) is applied first.
  - **`covers(pose, canvas)`.** The transformed picture's quad contains all four canvas corners.
  - **`faceAfter(box, pose, canvas)`.** The axis-aligned bounding box (canvas shares, 0..1 from the top-left) of a source-frame box after the pose.
  - **`centreAfter(box, pose, canvas)`.** The same for the box's centre point.
  - **Tests:**
    - scale 1, no shift: covers;
    - scale 1.25 with x ±0.25: covers at the edge, fails at 0.26;
    - rotation 5° at scale 1: fails (the corners show);
    - rotation 5° at scale 1.16: covers a 9:16 frame, and 1.15 does not (half-width needs 540·cos5° + 960·sin5° = 621.6 px, 1.151 of 540; corrected by Task 1);
    - a face box mapped under scale and shift.
- [ ] **Step 6: `checkMove(move, ctx)`.**
  - **The context:** `ctx = { canvas, cap, lengthS, faces: Box[] | null, shown: Box[], card: Box | null }`. `lengthS` is how long it plays; `faces` is null when unknown or none; `card` is the card's frame box for a card cutaway.
  - **It answers `{ ok: true } | { ok: false; why: string }`.** It samples every 1/30 s from 0 to `lengthS` (and each pose's `s`) and fails on the first of:
    - poses not in time order, or more than `MOVE_POSES_MAX`;
    - a scale below 1 or above `cap`;
    - `|rot| > ROT_MAX`;
    - for a main piece or a cover cutaway, `!covers(pose)`; for a card, the card after the pose leaves the frame;
    - a face box not fully inside [0,1]² after the pose;
    - a shown box's centre off screen after the pose.
  - **Tests:** one passing move and one per failure, with the `why` texts in plain English.
- [ ] **Step 7.** Run `npm test` and `npm run typecheck`.

### Task 4: Core: writing moves as keyframes

  - **Return:** `{ info, kept, dropped }`.
  - **Tests:**
    - keyframe times in source time, with speed;
    - the merge of two moves;
    - the seam;

### Task 5: Main: placement, views and the zoomed face

**Files:** Create `apps/desktop/src/main/move-cues.ts`, `move-cues.test.ts`. Modify `footage.ts` (video width and height on clips, from the bin), `packages/core/src/planner/footage.ts` (`FootageClip.width?`, `height?`).

- [ ] **Step 2: `movesInForce(input)`.** Mirror `composedInForce` and `graphicsInForce`. Each stored `isMove` cue goes through these steps:
  1. **Level.** It is skipped (not counted) when `from` is above the level, or when its point is set but not placed.
  2. **Place.**
     - A main move is placed by its word (`itemPlaceOf`); an insert move by its cutaway's place.
     - With no place it is counted `lost`, unless it is off.
  3. **Length.** It plays from its place until the earlier of its last pose's `s` and its piece's (or cutaway's) end. It is cut at the piece's end.
  4. **Overlap.** Two moves on one piece that overlap in time: the later is dropped and counted.
  5. **Check.**
     - It runs `checkMove` with the canvas and the cap from the clip's width and height.
     - `faces` are the face boxes of the scenes the piece plays during the move (objects with `face`, or every keep box when `face` is absent on all objects of that clip, or the `keepClear` band as a full-width box when there are no objects).
     - `shown` are the non-face keep boxes, and `card` comes from the cutaway framing.
     - A failure drops it and counts it as `dropped`; for an off move it is kept in the off list with its `why`.

  Return `{ kept: PlacedMove[], off, dropped, lost }`, where `PlacedMove = { cue, atUs, durationUs, cut | insertIndex, startUs }`.
