# 0.4.2: แก้เวลาซูม และตัวเลือก "มี CapCut Pro"

- สถานะ: ออกแบบแล้ว ผู้ใช้เลือกแนวทาง 2026-09-29 (ตั้งค่าในแอป · ของที่ยังไม่รู้ถือว่า Pro · แก้บั๊กออก 0.4.2 ก่อนทำฟีเจอร์ตัวหนังสือหลังคน)
- ที่มา: การทดลองตัวหนังสือหลังคนบน 0917 (2026-09-29) เจอบั๊กสองตัวที่กระทบลูกค้าตอนนี้

## 1. ที่มา

### 1.1 ซูมผิดเวลา

- CapCut นับ `time_offset` ของ keyframe บนชิ้นวิดีโอ **จากต้นไฟล์ต้นฉบับ** ไม่ใช่จากต้นชิ้น
- หลักฐาน: export 0917 จาก CapCut 9.5 วัดตำแหน่งสายไฟบนผนังทีละช่วงเวลา
  - ชิ้นที่ 1 (ไฟล์เริ่มที่ 1.8 วิ ตั้ง punch ไว้ 3.145–3.495) ซูมจริงที่ 1.35–1.7 วิบนไทม์ไลน์
  - ชิ้นที่ 3 และ 6 (ไฟล์เริ่มที่ 10.1 และ 26.6 วิ) ซูมค้าง 1.15 ตลอดชิ้น เพราะเวลาของ keyframe เลยมาแล้วทั้งหมด
  - หลังบวกจุดเริ่มในไฟล์ของแต่ละชิ้นเข้าไป export รอบสองซูมตรงเวลาทุกชิ้น
- `packages/core/src/capcut/zoom.ts` เขียนเวลานับจากต้นชิ้นมาตั้งแต่ M10.3 (0.1.x–0.4.1): ซูมของลูกค้าจึงลงเร็วเกินหรือค้างทั้งชิ้น
- ที่ไม่เคยเห็นเพราะ keyframe ที่ CapCut เขียนเองใน 0815 อยู่บนชิ้นที่ไฟล์เริ่มที่ 0 ซึ่งสองแบบให้ผลเท่ากัน

- ผู้ใช้ตัดสิน: ของที่ยังไม่รู้ **ถือว่าเป็น Pro** จนกว่าจะเช็กได้
- แอปรู้เองไม่ได้ว่าบัญชีเป็น Pro ไหม (ค้น Config, MMKV, cache แล้วไม่มี · โฟลเดอร์ของแอป CapCut ใน Library macOS ไม่ให้อ่าน) ผู้ใช้เลือกให้เป็นตัวเลือกในแอป

ทำ:

## 3. แก้เวลาซูม

- `addZooms` เขียน `time_offset = source_timerange.start + at × speed` โดย `at` ยังเป็นเวลาในชิ้นเหมือนเดิม
  - `speed` อ่านจากชิ้น ไม่มีค่าถือเป็น 1 · `source_timerange` เป็น null ได้ในชนิด ถ้า null ถือว่าเริ่มที่ 0
- ไม่มีที่ไหนอ่าน keyframe กลับจากดราฟต์ (ซูมที่เห็นในแอปมาจากโครงเรื่องที่เก็บไว้) และโครงเรื่องเก็บซูมเป็นจุดอ้างอิง ไม่ใช่เวลาใน keyframe: **ไม่ต้องแปลงข้อมูลเก่า** การเขียนครั้งต่อไปของทุกโปรเจคได้ซูมที่ถูกเวลาเอง
- เอกสาร: สเปกหลักบรรทัดรูปแบบ keyframe เปลี่ยนเป็น "µs นับจากต้นไฟล์ต้นฉบับ (source time)" · คอมเมนต์ใน `capcut/types.ts`
- ทดสอบ: ชิ้นที่ไฟล์เริ่มไม่ใช่ 0 และชิ้นที่ `speed` ไม่ใช่ 1 (เทสต์เดิมใช้ชิ้นที่เริ่มที่ 0 จึงจับบั๊กนี้ไม่ได้) · แก้ค่าที่คาดใน `flair.test.ts` และ `flair-plan.test.ts` ที่เทียบ `time_offset` กับเวลาบนไทม์ไลน์

## 4. ตัวเลือก "มี CapCut Pro"

### 4.1 การตั้งค่า

- `AppSettings.capcut = { pro: boolean }` ค่าเริ่มต้น `false` เป็นหมวดบนสุดของตัวเอง (ไม่ใส่ใน `FlairOptions` เพราะ IPC สร้าง `flair` ใหม่ทีละช่องและจะทิ้งช่องที่ไม่รู้จัก)
- ต้องเพิ่มทุกที่ที่ settings ผ่าน: `DEFAULT_SETTINGS` · การอ่าน (`read`) · การบันทึก (`update` สร้าง object ใหม่จากหมวดที่รู้จักเท่านั้น) · `SettingsPatch` ทั้งฝั่ง main และ `shared/api.ts` · `SettingsView`
- หน้าตั้งค่า แท็บทั่วไป ต่อจากแถวหน้าตา:
  - ชื่อ: **มี CapCut Pro**
  - คำอธิบาย: "เปิดเมื่อบัญชี CapCut ของคุณเป็น Pro · ถ้าปิด แอปจะไม่ใส่ของที่ต้องใช้ Pro เพื่อให้ export ได้โดยไม่ต้องสมัคร"
- เครื่องที่อัปเดตจาก 0.4.1 ได้ค่าปิด (ไม่มีค่าเดิม) การเขียนครั้งต่อไปจึงตัดของ Pro ออก และหน้าเขียนบอกว่าตัดไปเท่าไร

### 4.2 ป้าย Pro ในรายการของแอป

- `ExitAnimation` มีช่อง `pro: boolean` ตามตาราง §1.2: ทั้งห้าเป็น true (spin-out ตาม cache · fade-alt ตามหน้าต่าง export ตั้งแต่ 0.4.3 ส่วน 0.4.2 ตั้งเป็น false ตาม cache ซึ่งผิด · fade-out, fade-dim, burst-out ไม่เคยเห็นว่าฟรี) พร้อมคอมเมนต์ว่าอันไหนเช็กจากอะไร อันไหนยังไม่รู้และถือว่า Pro ตามที่ผู้ใช้ตัดสิน · ปิด Pro จึงไม่มีแอนิเมชันตอนหายไปเลย
- แอนิเมชันเข้าของสไตล์ (`styles.ts`) เป็นของฟรีทั้งหมด: `HighlightAnimation` มี `pro: false` และมีเทสต์กันไม่ให้สไตล์ที่เลือกได้ใช้แอนิเมชัน Pro
- เสียง: เสียงที่ `effectId` อยู่ในรายการที่มากับแอปคือของฟรี แม้รายการในเครื่องจะอ่านมันมาจากโปรเจค (ได้ไฟล์และความยาวจริงจากดราฟต์) · เสียงอื่นที่อ่านจากโปรเจคในเครื่องถือว่าต้องมี Pro

### 4.3 เมื่อปิด Pro: กรองตอนแสดงและตอนเขียน ไม่แตะของที่เก็บไว้

หลัก: ของที่เก็บไว้ในโครงเรื่องอยู่เหมือนเดิม (ถ้าผู้ใช้เปิด Pro ทีหลังก็กลับมาครบ) การกรองทำตอนแสดงตัวอย่างและตอนเขียนเท่านั้น

- **Claude:**
  - รายการแอนิเมชันตอนหายไปในข้อความที่ส่งให้ Claude มีเฉพาะของฟรี (อยู่ในข้อความ ไม่ใช่ system prompt จึงไม่กระทบรุ่นของ prompt) · ตั้งแต่ 0.4.3 ไม่มีแอนิเมชันตอนหายไปที่ฟรี ปิด Pro รายการนี้จึงว่าง ข้อความบอก "(ไม่มีให้เลือก ให้ตอบค่าว่าง)" แทน
  - คำตอบที่เลือกแอนิเมชัน Pro มาอยู่ดี ถือว่าไม่มีแอนิเมชัน และนับเป็นของที่ตกไป
  - รายการเสียงที่ส่งให้ Claude มีเฉพาะเสียงที่มากับแอป
- **ของที่ผู้ใช้เลือกเอง:**
  - แอนิเมชัน Pro ที่เก็บไว้ยังอยู่ แต่ตอนแสดงและตอนเขียนเป็น "ไม่มีแอนิเมชัน"
  - เสียงจากโปรเจคอื่นที่เก็บไว้ยังอยู่ แต่ไม่วางลงดราฟต์
  - การให้ AI คิดเสียงใหม่ **ไม่ลบ** เสียงที่ผู้ใช้แก้เองซึ่งถูกกันเพราะ Pro (ยังลบเฉพาะเสียงที่เครื่องไม่มีจริงเหมือนเดิม)
- **เมนูแก้ลุค:**
  - ตัวเลือกแอนิเมชันตอนหายมีเฉพาะของฟรีกับ "ไม่มี" · ตั้งแต่ 0.4.3 ไม่มีของฟรี ปิด Pro รายการจึงว่าง เหลือแค่ "หายเฉยๆ" เมนูขึ้นบรรทัด `flair.exit.allPro` ("แอนิเมชันตอนหายไปทุกแบบต้องมี CapCut Pro (ถ้ามี เปิด “มี CapCut Pro” ในตั้งค่า)") ใต้ช่องเลือก และปิดช่องนั้น เว้นแต่ชุดนั้นเก็บแอนิเมชัน Pro ไว้ (ช่องยังเปิดให้เลือก "หายเฉยๆ" ได้)
  - ถ้าชุดนั้นเก็บแอนิเมชัน Pro ไว้ เมนูแสดงตัวนั้นเป็นตัวที่เลือกอยู่ พร้อมคำว่า "(ต้องมี CapCut Pro · ไม่ใส่ตอนเขียน)" และส่งค่าเดิมกลับเมื่อแก้อย่างอื่น เช่นรูปแบบหรือโทน จะได้ไม่ทับจนหาย
- **รายการเสียง:**
  - ตัวเลือกมีเฉพาะเสียงที่มากับแอป
  - เสียงที่เก็บไว้แต่ถูกกันไม่ขึ้นเป็นเสียงที่เล่น (เหมือนเสียงอื่นที่ไม่ได้เล่น)
  - มีบรรทัดแจ้งของตัวเอง: "มีเสียง N จุดที่ไม่ใส่ เพราะต้องมี CapCut Pro (ถ้ามี เปิด “มี CapCut Pro” ในตั้งค่า)"
  - บรรทัด "เครื่องนี้ไม่มีเสียงนั้น" ใช้กับเสียงที่หาไม่เจอจริงเท่านั้น
  - ถ้าผู้ใช้เลือกเสียงใหม่ในช่องนั้น เสียงใหม่แทนเสียงที่ถูกกัน (เป็นการเลือกของผู้ใช้เอง)
- **หน้าเขียน:**
  - สรุปก่อนเขียนมีบรรทัด "ของที่ต้องมี CapCut Pro ไม่ใส่: แอนิเมชันตอนหายไป N · เสียง M (ถ้ามี เปิด “มี CapCut Pro” ในตั้งค่า)" เฉพาะเมื่อมีอย่างน้อยหนึ่ง
  - ผลหลังเขียน (`WriteResult`) มีตัวเลขเดียวกัน

### 4.4 เมื่อเปิด Pro

ทำงานเหมือน 0.4.1 ทุกอย่าง: แอนิเมชันทั้งห้าและเสียงจากโปรเจคอื่นใช้ได้

### 4.5 กฎสำหรับงานต่อไป

ของ CapCut ที่จะเพิ่มในแอปทุกชิ้น (แอนิเมชัน เสียง เอฟเฟค การลบพื้นหลัง ฯลฯ) ต้องมีป้าย Pro ที่เช็กจาก cache ของ CapCut ก่อน ไม่รู้ = Pro

ตั้งแต่ 0.4.3: หน้าต่าง export ของ CapCut เป็นตัวตัดสิน ก่อน cache (cache บอกว่าอัลเทอร์เนตเฟดฟรี แต่หน้าต่าง export ขึ้นเป็นของ Pro เมื่อ 2026-09-29 ดู §1.2)

## 5. ทดสอบ

- **เทสต์ใหม่หรือแก้:**
  - core: เวลาซูมบนชิ้นที่ไฟล์เริ่มไม่ใช่ 0 และ speed ≠ 1 · ป้าย Pro ใน `EXIT_ANIMATIONS` · รายการแอนิเมชันที่ส่ง Claude เมื่อปิดและเปิด Pro · `enforce` กับแอนิเมชัน Pro
  - main: settings อ่านและบันทึก `capcut.pro` ได้ (รวมเทสต์ที่เทียบ settings ทั้งก้อน) · ตัวอย่างและการเขียนเมื่อปิด Pro ไม่มี id ของ Pro และนับถูก · ของที่เก็บไว้ไม่หาย · คิดเสียงใหม่ไม่ลบเสียงที่ถูกกัน
  - renderer: สวิตช์ในหน้าตั้งค่า · เมนูลุคแสดงแอนิเมชัน Pro ที่เก็บไว้พร้อมป้ายและไม่ทับ · รายการเสียงไม่มีเสียง Pro · บรรทัดสรุปในหน้าเขียน
- เทสต์เดิมที่ใช้แอนิเมชัน Pro หรือเสียงปลอมจากโปรเจค ให้เปิด Pro ในเทสต์นั้น หรือเปลี่ยนไปใช้เสียงที่มากับแอป (แอนิเมชันตอนหายไปไม่มีตัวที่ฟรีแล้วตั้งแต่ 0.4.3 จึงต้องเปิด Pro)
- **เกณฑ์ผ่าน:** mutation ทุกไฟล์ที่แตะ · ทั้งชุดผ่าน · typecheck ผ่าน
- **ทดลองจริงบน 0917:** ใช้แอปที่ build แล้วกับโปรไฟล์ทดสอบ
  - ปิด Pro แล้วเขียน: ดราฟต์ต้องไม่มี id ของห้าแอนิเมชัน Pro (นับอัลเทอร์เนตเฟดด้วยตั้งแต่ 0.4.3) และไม่มีเสียงนอกรายการที่มากับแอป
  - `time_offset` ของซูมต้องเท่ากับจุดเริ่มในไฟล์ + เวลาในชิ้น
  - ผู้ใช้ export จาก CapCut แล้วต้องไม่ขึ้นเตือน Pro และซูมตรงเวลา
  - เสร็จแล้วคืน 0917
