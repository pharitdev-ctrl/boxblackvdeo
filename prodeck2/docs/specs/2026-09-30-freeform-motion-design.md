## 2. สิ่งที่พิสูจน์แล้ว (2026-09-30)

- ตัวเรนเดอร์ของแอป (HyperFrames 0.8.65 ในชุดเรนเดอร์ รันแบบตัดเน็ตเหมือนที่แอปรัน) เล่นแอนิเมชัน CSS และ Web Animations ได้ตรงทุกเฟรม โดยไม่ต้องมีไลบรารี: หน้าเพจมีสคริปต์ตัวกลาง (host) ที่ตั้ง `currentTime` ของทุกแอนิเมชันใน `document.getAnimations()` และเรียก `window.frame(t)` ถ้ามี · จุดวัดคลาดไม่เกิน 1 px ทุกเฟรมที่ตรวจ · ได้ ProRes 4444 โปร่งใสเหมือนกราฟิกเดิม
- ใส่ Content-Security-Policy `default-src 'none'` ได้โดยภาพไม่เปลี่ยน (ต้องมี `font-src data:` เพราะ HyperFrames ฝังฟอนต์เป็น data URI)
- ชิ้นงานที่ตั้งใจหนีออก (ข้ามตัวตรวจโค้ด) ยิงไปที่ตัวรับบนเครื่อง: CSP กัน fetch รูป beacon CSS iframe และฟอร์ม · Chrome ที่ห่อด้วยพร็อกซีตายกันทุกอย่างที่ออกนอกเครื่อง และ `--block-new-web-contents` กันหน้าต่างใหม่ · สคริปต์ `spike/chrome-offline.sh` `spike/adversarial.html` `spike/listen.py`
- ตัวกลางรุ่นที่สอง (`spike/host-v2.js`) จับ error จาก `window.frame` แล้วพิมพ์ออก HyperFrames พิมพ์ต่อให้เป็น `[Browser:ERROR] BOXBLACK motion error: …` แม้ในโหมดเงียบ ภาพของชิ้นงานปกติไม่เปลี่ยน (ต่างกันในระดับสัญญาณรบกวนระหว่างรอบเรนเดอร์)
- การเรนเดอร์ไม่ได้ผลเหมือนกันทุกไบต์ระหว่างรอบ (ต่างในระดับ 58–68 dB) จึงเทียบภาพด้วย PSNR ไม่ใช่ md5
- Claude 5 รอบแยกกันเขียน 5 ชิ้นจากคำพูดใน 0917 ด้วยกติกาชุดเดียว เรนเดอร์ผ่านครั้งแรกทุกชิ้น ภาษาไทยไม่เพี้ยน หน้าตาเป็นชุดเดียวกัน
- เรียก `claude -p` แบบที่แอปเรียก: 51 วินาทีต่อชิ้น (ออก ~4,900 token) · เรนเดอร์ 3–5 วินาที · ไฟล์ 21–33 MB ต่อชิ้นยาว 3–4 วินาที ที่ 1080×900 (~8 MB/วินาที)
- ตัวแปรเวลาคำพูดและตัวแปรสี (§5.3 §5.4) ลองแล้วหนึ่งชิ้นด้วยกติกาฉบับสุดท้าย (`spike/contract-final.md`): Claude ใช้ `var(--wN)` 13 ที่ ไม่พิมพ์รหัสสีเลย เรนเดอร์ผ่านครั้งแรก และเมื่อเปลี่ยนค่าเวลาของคำ จังหวะในภาพเลื่อนตาม · เรียก 43 วินาที
- **หลังงานที่ 1 เสร็จ (2026-09-30):** หน้าเพจที่โค้ดใน core สร้างเอง (`motionHtml` กับ `host.js` ของแอป) เรนเดอร์ผ่านชุดเรนเดอร์จริงและ Chrome ที่ตัดเน็ต ตรวจภาพผ่าน · ชิ้นเดียวกันเปลี่ยนสีตามสไตล์ 3 แบบได้โดยไม่ต้องเรียก Claude (`spike/e2e.mts`)
- **ลองกติกาฉบับสุดท้ายด้วยการเรียกจริง 8 ครั้ง** (โจทย์ 8 แบบ 3 หัวเรื่อง `spike/trial-r1/`): ผ่านตัวตรวจโค้ดครั้งแรก 8 จาก 8 · เรนเดอร์ได้ มีภาพ และหายหมดตอนจบ 8 จาก 8 · เรียกครั้งละ 27–39 วินาที (ออก 2,100–4,000 token) · เรนเดอร์ 3.0–4.4 วินาที
- หนึ่งใน 8 ชิ้นผ่านทุกด่านแต่ภาพผิด: ไอคอน 3 ตัวไปกองที่มุมเวที เพราะกลุ่ม SVG มี attribute `transform` และมีแอนิเมชันของ `transform` ซึ่งเขียนทับ attribute · ตัวกลางรุ่นที่สาม (`spike/host-v3.js`) ตรวจเรื่องนี้ก่อนวาดเฟรมแรกแล้วพิมพ์ออกแบบเดียวกับ error ของ `window.frame` · ไม่เตือนผิดในอีก 13 ชิ้น · เรียกซ่อมจริงหนึ่งครั้ง (20 วินาที) ได้ชิ้นที่ถูกกลับมา · วงจรเขียน ตรวจ เรนเดอร์ ซ่อม เรนเดอร์ซ้ำ จึงลองครบแล้วหนึ่งรอบด้วยของจริง
- ยังไม่ได้พิสูจน์: วางลงดราฟต์แล้วเปิดใน CapCut (ไฟล์ชนิดเดียวกับกราฟิกเดิม) · อัตราพลาดเมื่อใช้หลายคลิป · คุณภาพของรอบวางแผน (ไอเดีย) กับคลิปจริง

## 3. ภาพรวมการทำงาน

1. **วางแผน (หนึ่งครั้งต่อคลิป):** Claude ดูจุดเน้นและภาพ แล้วตอบว่าจุดไหนควรมีกราฟิก เริ่มที่คำไหน อยู่ถึงคำไหน ยาวกี่วินาที วางกล่องตรงไหน เหตุผล และ **ไอเดีย** ว่าจะวาดอะไร · Claude ไม่เห็นเวลาของแต่ละคำ จึงบอกแค่คำสุดท้ายที่ไอเดียใช้เป็นจังหวะ แอปรู้เวลาจริงและยืดความยาวให้ถึงคำนั้นบวก 1 วินาทีเอง (ไม่เกิน 6 วินาที)
2. **เขียน (หนึ่งครั้งต่อชิ้น ทำพร้อมกันได้ 3 ชิ้น):** Claude ได้กติกา (§5) ขนาดเวที ความยาว คำที่พูดพร้อมเวลา ไอเดีย และสี แล้วตอบเป็นโค้ดชิ้นเดียว
3. **ตรวจ:** แอปตรวจโค้ด (§6.1) เรนเดอร์ แล้วตรวจภาพ (§6.2) · ไม่ผ่านส่งกลับให้ Claude ซ่อม **หนึ่งรอบ** พร้อมบอกว่าผิดอะไร · ยังไม่ผ่านชิ้นนั้นเก็บเหตุผลไว้และขึ้นว่าล้มเหลว
4. **ใช้:** ชิ้นที่ผ่านเล่นในพรีวิว และเขียนลงดราฟต์เป็นเลเยอร์ใสแบบเดิม (`addGraphicTrack` ไม่เปลี่ยน)

งานทั้งหมดอยู่ในงาน "กราฟิก" ของรอบวางแผนเดิม (`workTwo`) ระหว่างเขียน แถบแผนบอก "กำลังเขียนกราฟิก 2 จาก 5" · กด "หยุด" หยุดได้ทุกช่วง รวมตอนที่ชิ้นกำลังเรนเดอร์ตรวจ: งานจบทันที ชิ้นที่เขียนเสร็จแล้วยังอยู่ ชิ้นที่ยังตรวจไม่จบไม่ถูกเก็บ (ขึ้นว่ายังไม่ได้เขียน กดทำใหม่ได้) เรนเดอร์ที่ค้างอยู่ปล่อยให้จบเองเบื้องหลัง

**หนึ่งที่ หนึ่งชิ้น:** กราฟิกถูกระบุด้วยจุดที่มันเริ่ม (anchor) ทุกที่ ทั้งตอนเก็บผลการเขียน ปุ่มปิด ลบ ลองเรนเดอร์ใหม่ และทำใหม่ ถ้า Claude ตอบสองชิ้นที่เริ่มคำเดียวกัน แอปเก็บชิ้นแรก ทิ้งชิ้นหลังและนับเป็นชิ้นที่ใช้ไม่ได้ · ชิ้นของ Claude ที่รอจุดซึ่งตอนนี้ถูกตัดออก ถ้าอยู่ที่เดียวกับชิ้นของผู้ใช้หรือชิ้นใหม่ ชิ้นที่รอถูกทิ้ง

## 5. กติกาที่ให้ Claude (contract)

อยู่ใน core เป็นค่าคงที่ภาษาอังกฤษ มีรุ่นกำกับ ข้อความเต็มที่ลองแล้วอยู่ที่ `docs/plans/2026-09-30-freeform-motion-notes/spike/contract-final.md`

### 5.1 รูปแบบ
- ตอบเป็นชิ้นเดียว: `<style>` ตามด้วย markup และ `<script>` ได้หนึ่งบล็อก ไม่มี `<html>` `<head>` `<body>` ไม่มีไฟล์หรือ URL ภายนอก
- เขียนแท็กแบบเรียบ: ค่า attribute อยู่ในเครื่องหมายคำพูด ไม่มี `<` `>` ในค่า · เครื่องหมายน้อยกว่าในข้อความเขียนเป็น `&lt;` · ปิด `<svg>` ทุกตัวก่อนสคริปต์ · ไม่มีคอมเมนต์ HTML
- ในสคริปต์: บอกชื่อที่ใช้ได้พอสำหรับทุกชิ้น (`getElementById` `querySelector` `createElementNS` `setAttribute` `appendChild` `textContent` `style` `el.animate()` `getTotalLength()` `getPointAtLength()` `Math` `window.frame`) และชื่อที่ห้าม (§6.1) · สคริปต์รันครั้งเดียวทันที ไม่รอ event
- วางในเวทีโปร่งใสขนาด W × H px ที่แอปกำหนด ห้ามวาดนอกเวที ที่ไม่ได้ทาสีคือวิดีโอ

### 5.2 เวลา
- ใช้ได้แค่ CSS animation กับ Web Animations API ทุกแอนิเมชันเล่นครั้งเดียว มี delay นับจากเวลา 0 และ fill both
- ห้าม `requestAnimationFrame` `setTimeout` `setInterval` `Date` `performance.now` `Math.random` และ transition ที่เกิดจากการสลับคลาส เพราะตัวเรนเดอร์ตั้งเวลาเองทีละเฟรม
- ของที่ต้องคำนวณทุกเฟรมให้ตั้ง `window.frame = (t) => { … }` ซึ่งต้องวาดเหมือนเดิมเมื่อ `t` เท่าเดิม
- ทางออกต้องจบและหายหมด (มองไม่เห็น) ก่อนเวลา D 0.1 วินาที และเผื่อราว 0.4 วินาทีสุดท้ายไว้ให้ทางออก

### 5.3 เวลาของคำพูดเป็นตัวแปร
- แอปให้เวลาของแต่ละคำเป็นตัวแปร CSS `--w1` … `--wN` (วินาที ไม่มีหน่วย) และเป็นอาร์เรย์ `T` ในสคริปต์ (`T[0]` คือคำแรก)
- delay ที่ผูกกับคำต้องเขียนจากตัวแปร เช่น `animation-delay: calc(var(--w2) * 1s - 0.3s)` หรือ `delay: T[1] * 1000 - 300` ห้ามพิมพ์เลขเวลาของคำลงไปตรง ๆ
- เหตุผล: เมื่อผู้ใช้แก้การตัด เวลาของคำเลื่อน แอปเรนเดอร์ใหม่ด้วยค่าใหม่ได้โดยไม่ต้องเรียก Claude

### 5.4 หน้าตา
- ข้อความเป็นภาษาไทย ฟอนต์ตั้งไว้ที่เวทีแล้ว ห้ามระบุฟอนต์หรือ `font-weight` · ตัวเล็กสุด 44 px ที่เฟรมกว้าง 1080 · ห่างขอบเวทีอย่างน้อย 40 px · ห้ามทำแอนิเมชันทีละตัวอักษร (วรรณยุกต์กับสระจะหลุด)
- อยู่บนวิดีโอที่ขยับ: ข้อความต้องมีพื้นทึบรองหรือเส้นขอบเข้มหนา ห้ามทาสีโปร่งแสงทับพื้นที่ใหญ่
- สีใช้ตัวแปรที่แอปให้: `--text` `--accent` `--alt` `--bar` (จากสไตล์ข้อความเด่นที่เลือก) กับ `--ink` (เส้นขอบเข้ม) และ `--paper` (ขาว) ห้ามพิมพ์รหัสสีอื่น ยกเว้นเฉดที่ผสมจากสีในชุดด้วย `color-mix()`
- Claude ไม่รู้ว่าสีจริงคืออะไร จึงบอกว่ามีแค่สองคู่ที่อ่านออกแน่: `--text` บนแผ่น `--bar` และ `--ink` บนแผ่น `--paper` · `--accent` กับ `--alt` ใช้กับรูปทรง และกับตัวหนังสือใหญ่ที่มีเส้นขอบ `--ink` เท่านั้น · แอปรับประกันคู่แรกเอง: ถ้าสีตัวหนังสือของสไตล์อ่านไม่ออกบนแถบ (สไตล์ที่ผู้ใช้กำหนดเอง) `--text` จะเป็นดำหรือขาวที่อ่านออกแทน
- ใน SVG แอนิเมชันของ `transform` เขียนทับ attribute `transform` ของตัวเอง จึงให้วางตำแหน่งด้วย `<g transform="translate(x y)">` ชั้นนอก แล้วขยับ `<g>` ชั้นใน · ของที่ย่อขยายหรือหมุนอยู่กับที่ใส่ `transform-box: fill-box; transform-origin: center`
- ภาพวาดด้วย SVG ในตัว รูปทรงเรียบ หนา ชัด · ไม่ใช้อีโมจิ ไม่ใช้รูปภาพ
- ความคิดเดียว จุดสนใจเดียวต่อครั้ง ข้อความบนจอไม่เกินราว 12 คำไทย
- ไม่เกิน 160 บรรทัด

## 6. การตรวจ

### 6.1 ตรวจโค้ด (ก่อนเรนเดอร์ และอีกครั้งตอนเรนเดอร์)
โครงของชิ้นงานต้องตายตัว เพื่อให้ตัวตรวจกับตัวอ่าน HTML ของ Chrome เห็นตรงกันเสมอ ตัวตรวจมีสองส่วน: **ตัวอ่านโครง** (`motion/shape.ts`) อ่านชิ้นงานตามลำดับที่เบราว์เซอร์อ่าน และปฏิเสธทุกอย่างที่อ่านให้แน่ใจไม่ได้ กับ **ตารางกฎ** (`motion/lint.ts`) ที่ตรวจแต่ละส่วน ทุกปัญหาบอกว่าเจออะไรและให้ทำอะไรแทน เพราะข้อความนี้ส่งให้ Claude ตอนซ่อม

- **โครง:** ต้องขึ้นต้นด้วย `<style>` หนึ่งบล็อก (ไม่มี attribute ปิดด้วย `</style>` เรียบ ๆ) ตามด้วย markup และ `<script>` ได้ไม่เกินหนึ่งบล็อก (ไม่มี attribute) ซึ่งต้องปิดและอยู่ท้ายสุด · ห้ามมี `<style` หรือ `<script` ตัวที่สอง (รวมใน CSS และใน SVG) · ห้าม `</script` ในโค้ด
- **สิ่งที่ตัวอ่านโครงปฏิเสธ:** `<` ที่ไม่ได้เปิดแท็ก (คอมเมนต์ `<!--` `<!…>` `<?…>` CDATA) · แท็กหรือเครื่องหมายคำพูดที่ไม่ปิด · ชื่อแท็กหรือ attribute ที่มีเครื่องหมายคำพูด `=` หรือ backtick · `<` หรือ `>` ในค่า attribute · `<svg>` หรือ `<math>` ที่เปิดค้างหรือปิดเกิน (ข้างในนั้นตัวอ่านของเบราว์เซอร์อ่านสคริปต์เป็น markup) · อักขระ NUL
- **ขนาด:** ว่างเปล่า หรือยาวเกิน 40 KB (เกินแล้วไม่ตรวจต่อ)
- **แท็กต้องห้าม:** `<html` `<head` `<body` `<meta` `<base` `<link` `<form` `<iframe` `<frame` `<frameset` `<object` `<embed` `<applet` `<portal` `<img` `<video` `<audio` `<canvas` `<template` และแท็กที่เบราว์เซอร์อ่านข้างในเป็นข้อความดิบ (`<textarea` `<title` `<xmp` `<plaintext` `<noscript` `<noembed` `<noframes`) และ SMIL (`<animate` `<animateTransform` `<animateMotion` `<set`) เพราะตัวเรนเดอร์ตั้งเวลาให้ไม่ได้ · โค้ดสร้างแท็กพวกนี้ด้วย `createElement` ก็ไม่ได้
- **ตัวจัดการเหตุการณ์ในแท็ก:** attribute `on…=` ทุกตัว และ `setAttribute("on…")` ในโค้ด
- **URL และไฟล์:** `src` `srcset` ทุกค่า · `href` ที่ไม่ใช่ `#…` · `url(` ที่ไม่ใช่ `url(#…)` · `@import`
- **ในโค้ด ต่อเน็ต โหลดโค้ด หรือสร้างโค้ดจากข้อความ:** `fetch` `XMLHttpRequest` `WebSocket` `EventSource` `sendBeacon` `RTC…` · `Worker` `SharedWorker` `ServiceWorker` `BroadcastChannel` `MessageChannel` `postMessage` · `import` `importScripts` `eval` `Function`
- **ในโค้ด หนีเวที:** `location` `navigation` `history.` `navigator.` การเรียก `open(` ทุกแบบ `document.write` `document.domain` `document.cookie` `localStorage` `sessionStorage` `indexedDB` · การเข้าถึงแบบคำนวณชื่อ `window[` `self[` `this[` `top[` `parent[` `document[` และ `globalThis` · การกำหนดค่า `.href` `.src` `.action` `.srcdoc` และ `setAttribute` ของชื่อเหล่านี้ · `.click(` `.submit(` `.requestSubmit(` `dispatchEvent(` · HTML จากข้อความ (`innerHTML` `outerHTML` `insertAdjacentHTML` `createContextualFragment` `DOMParser` `setHTMLUnsafe` `parseHTMLUnsafe`) · `\u` และ `\x` (สะกดชื่อต้องห้ามได้)
- **ในโค้ด คำสั่งเวลาที่ห้าม (§5.2)**
- **ในโค้ด ชื่อของตัวเรนเดอร์:** `__timelines` `__hf` `hyperframe` `__player` (HyperFrames ตัดสคริปต์ที่มีชื่อพวกนี้ทิ้ง) และการประกาศ `T` ที่ชั้นบนสุดของสคริปต์ (หน้าเพจประกาศให้แล้ว)
- **ไม่มีแอนิเมชันเลย** (ไม่มีทั้ง `@keyframes` `.animate(` และ `window.frame`)

รายงานปัญหาได้ไม่เกิน 12 ข้อ ข้อละหนึ่งบรรทัด · กฎของโค้ดตรวจเฉพาะข้อความในบล็อกสคริปต์ ตัวหนังสือบนจอ ชื่อคลาส และ CSS พูดคำพวกนี้ได้ · ชื่อตัวแปรทั่วไปอย่าง `parent` `frames` `top` ไม่ห้าม (เคยห้าม ถอดออกหลังตรวจซ้ำเพราะเสียรอบซ่อมโดยไม่ได้ความปลอดภัยเพิ่ม)

**สิ่งที่ตัวตรวจทำไม่ได้:** ชื่อที่ประกอบจากข้อความ (เช่น `this["loc" + "ation"]` ผ่านตัวแปรอื่น หรือ `a["cl" + "ick"]()`) ผ่านตัวตรวจแบบอ่านข้อความได้เสมอ ตัวตรวจจึงกันความผิดพลาดตรง ๆ และรูปแบบโจมตีพื้น ๆ ด่านที่บังคับจริงคือด่านที่สองกับสาม

**หลักฐาน:** สุ่มชิ้นงานหลายพันแบบเทียบกับตัวอ่าน HTML มาตรฐาน (parse5): ทุกชิ้นที่ตัวตรวจให้ผ่าน ข้อความสคริปต์ที่ตัวอ่านเห็นเท่ากับที่ตัวตรวจเห็นทุกตัวอักษร ไม่มี handler ไม่มีแท็กต้องห้าม · เทสต์ถาวรอยู่ใน `graphics-page.test.ts` · ผู้ตรวจอิสระพยายามสร้างชิ้นที่หลอกได้แล้วไม่สำเร็จ

**ด่านที่สอง หน้าเพจ:** CSP `default-src 'none'; style-src 'unsafe-inline'; script-src 'unsafe-inline'; font-src data: 'self'; img-src data: 'self'; connect-src 'none'; form-action 'none'; base-uri 'none'` · ลองแล้วกับชิ้นงานที่ตั้งใจหนีออก: fetch รูป beacon ไฟล์ CSS iframe และการส่งฟอร์ม ถูกกันหมด · CSP กันการเปลี่ยนหน้า (navigation) กับหน้าต่างใหม่ไม่ได้

**ด่านที่สาม Chrome ของตัวเรนเดอร์:** ทุกการเรนเดอร์รัน Chrome ผ่านสคริปต์ห่อที่ใส่ `--proxy-server=http://127.0.0.1:9 --proxy-bypass-list=<-loopback>;localhost;127.0.0.1;[::1] --force-webrtc-ip-handling-policy=disable_non_proxied_udp --block-new-web-contents` ต่อท้ายคำสั่งของ HyperFrames (Chrome ใช้ค่าตัวหลังเมื่อซ้ำ) · `<-loopback>` จำเป็น: ถ้าไม่ใส่ Chrome จะต่อไปยัง address แบบ link-local (169.254.x.x) ตรง ๆ โดยไม่ผ่านพร็อกซี (ผู้ตรวจงานที่ 3 เจอ ลองจริงแล้วใน `spike/link-local/`) · ลองแล้ว: การเชื่อมต่อออกนอกเครื่องทุกแบบตาย (รวมการเปลี่ยนหน้าไปเครื่องอื่นในวงแลน) หน้าต่างใหม่ถูกกัน ชิ้นงานปกติเรนเดอร์ได้เหมือนเดิม · ที่ยังเหลือ: โค้ดที่เล็ดรอดตัวตรวจแล้วเปลี่ยนหน้าไปพอร์ตอื่นบนเครื่องเดียวกัน (loopback) ยังส่งคำขอ GET ได้หนึ่งครั้ง การเรนเดอร์ชิ้นนั้นจะล้ม

### 6.2 ตรวจภาพ (หลังเรนเดอร์)
ใช้ ffmpeg ที่มากับแอป (`alphaextract` + `signalstats`) อ่านค่าความทึบสูงสุดของแต่ละเฟรม:
- ต้องมีอย่างน้อยหนึ่งเฟรมที่มีภาพ → ไม่มี = "ไม่มีอะไรถูกวาด"
- เฟรมสุดท้ายต้องโปร่งใสทั้งเฟรม → ไม่ใช่ = "ยังค้างอยู่บนจอตอนจบ" · เฟรมสุดท้ายของไฟล์อยู่ก่อนเวลา D หนึ่งเฟรม กติกาจึงให้ทางออกจบก่อน D 0.1 วินาที และข้อความแจ้งบอกตัวเลขนี้
- เรนเดอร์ล้ม (HyperFrames แจ้งผิด หมดเวลา 120 วินาที) → ใช้ข้อความผิดพลาดท้าย ๆ เป็นเหตุผล
- ตรวจไฟล์ตรงที่ HyperFrames เขียนไว้ ก่อนย้ายเข้าโฟลเดอร์กราฟิก ชิ้นที่ไม่ผ่านจึงไม่ทิ้งไฟล์ไว้ · ffmpeg อ่านไฟล์ชิ้นหนึ่งไม่ได้ถือเป็นความผิดของชิ้นนั้น ไม่ใช่ของเครื่อง (ffmpeg หายทั้งตัวจึงเป็นของเครื่อง)
- สคริปต์ของชิ้นงานพัง: HyperFrames จบด้วยรหัส 0 แม้หน้าเพจพัง แอปจึงอ่านข้อความที่มันพิมพ์ออกมาเอง
  - `[Browser:PAGEERROR] …` (ไวยากรณ์ผิด หรือ error ที่ไม่ได้จับ) → "สคริปต์ผิดพลาด: …"
  - `BOXBLACK motion error: …` (ตัวกลางพิมพ์ออก ครั้งเดียวต่อข้อความ และเรนเดอร์ต่อได้ไม่ต้องรอหมดเวลา) → ข้อความนั้น ถ้ามีหลายข้อความเอาสามข้อแรกที่ไม่ซ้ำ · มาจากสองกรณี: `window.frame` โยน error และ **SVG ที่มี attribute `transform` พร้อมแอนิเมชันของ `transform`** (ตัวกลางตรวจก่อนวาดเฟรมแรก บอกชื่อแท็กกับคลาส และบอกวิธีแก้)
  - `sub_timeline_readiness_timeout` (หน้าเพจไม่พร้อมใน 20 วินาที) → "หน้าเพจไม่พร้อม"
  - HyperFrames จบด้วยรหัสผิดพลาด (หน้าเพจเปลี่ยนหน้าไปที่อื่น หรือค้าง) → อ่านข้อความที่มันพิมพ์หาเหตุข้างบนก่อน ถ้าไม่เจอใช้ข้อความของแอปเอง ("ตัวเรนเดอร์วาดหน้าเพจไม่ได้ สคริปต์ต้องจบทันทีและห้ามออกจากหน้า") ไม่ส่งข้อความดิบให้ Claude เพราะมีชื่อภายในของตัวเรนเดอร์ที่ตัวตรวจห้ามใช้ · หมดเวลา 120 วินาที → "เรนเดอร์ไม่ทันเวลา"
  - เหตุที่เก็บไว้เป็นข้อความล้วน ข้อละหนึ่งบรรทัด (ไม่มีคำนำหน้า `Error:`) เพื่อส่งให้ Claude เป็นรายการได้ตรง ๆ
- **ความผิดของเครื่อง ไม่ใช่ของชิ้นงาน** (ไม่เสียรอบซ่อม ชิ้นงานที่ผ่านตัวตรวจโค้ดถูกเก็บไว้ รอจนเครื่องพร้อม): ชุดเรนเดอร์หายหรือเสีย · ffmpeg หาย · ฟอนต์หรือสคริปต์ตัวกลางของแอปอ่านไม่ได้ · โฟลเดอร์ทำงานหรือโฟลเดอร์กราฟิกเขียนไม่ได้ (ดิสก์เต็ม ไม่มีสิทธิ์) · **Chrome ของตัวเรนเดอร์เปิดไม่ขึ้น** (HyperFrames จบด้วยรหัสผิดพลาดโดยไม่เคยพิมพ์ว่าเปิดเบราว์เซอร์ได้)

### 6.3 ซ่อม
- ไม่ผ่าน §6.1 หรือ §6.2 → เรียก Claude อีกครั้งพร้อมโจทย์เดิมทั้งก้อน (ขนาดเวที ความยาว คำพูด ไอเดีย) รายการปัญหา และโค้ดเดิม ให้แก้ทุกข้อโดยไม่เปลี่ยนอย่างอื่น แล้วตอบโค้ดทั้งชิ้น จากนั้นตรวจใหม่
- ซ่อมได้ **หนึ่งรอบ** ต่อการเขียนหนึ่งครั้ง · ยังไม่ผ่านเก็บเหตุผลใน `failed` และ `html` เป็น `null`
- เครื่องเรนเดอร์ไม่ได้เลย (ยังไม่ติดตั้งชุดเรนเดอร์ หรือ ffmpeg หาย) ไม่ใช่ความผิดของชิ้นงาน: เก็บโค้ดที่ผ่าน §6.1 ไว้ ยังไม่ตรวจภาพ เมื่อเรนเดอร์ได้ทีหลังแล้วภาพไม่ผ่าน ชิ้นนั้นขึ้นว่าล้มเหลวพร้อมปุ่มทำใหม่

## 7. การวางและเวลา

- **กล่อง:** Claude เลือกในรอบวางแผน กว้าง 0.5–1.0 ของเฟรม สูง 0.15–0.5 อยู่ในที่ว่าง (เดิมตั้งต่ำสุด 0.2 แต่ข้อมูลจริงเหลือที่ราว 0.18 ระหว่างแถบห้ามบังกับพื้นที่ซับที่ 0.76) แอปปัดเป็นพิกเซลคู่ และเลื่อนหลบแนวตั้งแบบเดิม (หลบหน้า ข้อความเด่น แล้วจึงซับ) ขนาดเวทีไม่เปลี่ยนเมื่อหลบ · หลบไม่ได้ = ไม่ใส่ (นับเป็นของที่ตกไป เหมือนเดิม)
- **ชั้น:** เหมือนกราฟิกเดิม อยู่ใต้ข้อความเด่นและซับ
- **ข้อความเด่นของจุดตัวเอง:** กราฟิกไม่หลบ และข้อความนั้นไม่ขึ้นเมื่อกราฟิกเล่นได้จริง (§7.1) · ยังหลบข้อความเด่นของจุดอื่น keepClear และพื้นที่ซับ
- **ระดับ:** ผูกกับจุดเน้นและทำตามระดับเบา กลาง จัดเต็ม เหมือนเดิม ไม่มีโควตา
- **คำพูดเลื่อน:** ทุกครั้งที่วางใหม่ แอปหาคำของชิ้นนั้นในการตัดปัจจุบัน
  - คำครบและเรียงเหมือนเดิม → ใช้เวลาปัจจุบันเป็นค่าตัวแปร เรนเดอร์ใหม่เองถ้าค่าเปลี่ยน
  - คำไม่ครบหรือเปลี่ยน → ชิ้นนั้น **ค้าง** (stale): ไม่ใส่ตอนเขียน นับรวมกับกราฟิกที่ถูกข้าม แถวบอกว่า "การตัดช่วงนี้เปลี่ยนไป กดทำใหม่"
  - ช่วงที่เล่นได้สั้นลงกว่าตอนที่เขียน: สั้นลงไม่เกิน 0.3 วินาที (เช่นเปลี่ยนความกระชับของการตัด) ชิ้นนั้นเล่นเต็มความยาวเดิม ล้ำเข้าท่อนถัดไปเล็กน้อย · หลังใช้กฎทั้งหมดแล้วถ้ายังถูกตัดเกิน 0.1 วินาที (เช่นชนปลายคลิป หรือสั้นลงเกิน 0.3) → ค้าง เพราะไฟล์จะถูกตัดก่อนทางออกจบ และเวลาที่พิมพ์ไว้ในโค้ดขยับเองไม่ได้
  - ชิ้นที่เขียนตามกติการุ่นอื่น (`version` ไม่ตรงกับรุ่นปัจจุบัน) → ค้าง
  - ข้อจำกัดที่รู้: ชิ้นที่เขียนในช่วงแคบจะสั้นอยู่อย่างนั้นแม้การตัดจะหลวมขึ้นทีหลัง (ต้องคิดใหม่ทั้งชุดจึงจะได้ความยาวตามแผน) · เปลี่ยนขนาดเฟรมของโปรเจกต์ไม่ทำให้ค้าง
- **เขียนตามที่ว่างจริง:** ตอนเขียน (และตอนทำใหม่) แอปใช้ความยาวที่ชิ้นนั้นเล่นได้จริงบนการตัดตอนนั้น (ความยาวจากแผน หรือถึงปลายท่อนที่ภาพตัดไปที่อื่น แต่ไม่ต่ำกว่า 1.5 วินาที) และคำที่พูดในช่วงนั้น แล้วเก็บความยาวกับคำชุดนั้นไว้กับโค้ด · การกด "ทำใหม่" กับชิ้นที่ค้างจึงเขียนให้พอดีกับการตัดปัจจุบัน
- **ที่ว่างจริงบนเฟรม (ดูจากข้อมูลโปรเจคจริง 2026-09-30):** แถบที่ห้ามบัง (หน้าและตัวคน) มักกินช่วง 0.2–0.6 ของความสูง บางฉากถึง 0.1–0.9 ที่ว่างจึงเหลือราว 0.2–0.4 ของความสูง (เวทีสูง 384–768 px ที่เฟรม 1080×1920) และบางฉากไม่มีที่เลย ชิ้นของฉากนั้นจะไม่ถูกใส่ · ตอนทดสอบจริงต้องนับว่ามีกี่ชิ้นที่ตกเพราะไม่มีที่
- **เสียง:** ช่องเสียงของกราฟิกใช้ข้อความ "กราฟิกขึ้น: <ไอเดีย>" กลไกเสียงที่ผูกกับกราฟิกไม่เปลี่ยน

### 7.1 กราฟิกแทนข้อความเด่นของจุดนั้น (ผู้ใช้ตัดสิน 2026-09-30)

ลองจริงบน 0917 ที่ระดับจัดเต็ม: ทุกจุดมีข้อความเด่นอยู่แถบเหนือหัว หน้าคนกินแถบ 0.22 ถึง 0.64 ซับเริ่มที่ 0.76 เหลือที่ว่าง 0.12 ซึ่งเล็กกว่ากล่องเล็กสุด (0.15) Claude จึงตอบว่าไม่มีกราฟิกเลย ผู้ใช้เลือกให้ **ข้อความเด่นของจุดที่มีกราฟิกหลบ ซับอยู่ครบ** (ทางเลือกที่ให้ซับหลบด้วยไม่เอา)

- **กราฟิกไม่หลบข้อความเด่นของจุดตัวเอง** ยังหลบ keepClear พื้นที่ซับ และข้อความเด่นของจุดอื่นที่ขึ้นระหว่างมันเล่น
- **ข้อความเด่นของจุดไม่ถูกวาดเมื่อกราฟิกของจุดนั้นเล่นได้จริง** คือเปิดอยู่ จุดผ่านระดับ มีที่ลง เขียนแล้ว และไม่ต้องทำใหม่ · กราฟิกที่ยังไม่ได้เขียน ต้องทำใหม่ ปิดอยู่ หรือไม่มีที่ลง ข้อความเด่นขึ้นตามเดิม จุดจึงไม่ว่างเปล่า
- **ลำดับคิดรอบเดียว:** วางและจับเวลาข้อความเด่นทุกชุดตามเดิม วางกราฟิกโดยหลบแถบของชุดพวกนั้น (ยกเว้นของจุดตัวเอง) แล้วค่อยทำเครื่องหมายชุดที่ถูกแทน
- **ชุดที่ถูกแทนไม่ถูกวาดเป็นข้อความ:** ไม่เขียนแทร็กข้อความ ไม่ซ่อนคำในซับ (เมื่อเปิด "ไม่ใส่ซับช่วงที่มีข้อความเด่น" ซับจะพูดคำนั้นเอง) ไม่นับในกล่องยืนยันก่อนเขียน · แต่บรรทัดของมันยังเป็นจังหวะของคลิป: เสียง สื่อแทรก และซูมกระชากที่ผูกกับบรรทัดยังเล่นตามเดิม
- **หน้าจอ:** แถวของชุดที่ถูกแทนขึ้น "มีกราฟิกแทน ไม่ขึ้นในคลิป" ยังแก้และลบได้ · ไม่มีกราฟิกเลยจะบอกเหตุผลว่า AI ใส่เฉพาะจุดที่เหมาะและมีที่ว่างพอ
- **Claude ตอนวางแผน** ได้แถบข้อความเด่นของแต่ละจุด และรู้ว่าข้อความของจุดที่ใส่กราฟิกจะไม่ขึ้น กราฟิกจึงพาคำสำคัญไปเองได้ · ลองจริงกับคำขอเดิมที่เคยได้ 0 ชิ้น ได้ 3 ชิ้นในแถบเหนือหัว (972×290)
- **ข้อจำกัดที่รับ:** กราฟิกเป็นแถบเตี้ย (สูง 15% บน 0917) · ฉากคนพูดของผู้ใช้ 34 จาก 60 ฉากมีที่ลง · เรนเดอร์ล้มตอนเขียนลงดราฟต์ จุดนั้นไม่มีทั้งข้อความและกราฟิกในรอบนั้น (แอปรายงานว่ากราฟิกถูกข้าม)

## 8. หน้าจอ (0.5.0)

แท็บกราฟิกและเทคนิค ส่วนกราฟิก แต่ละแถวมี:
- ภาพนิ่งตัวอย่าง (โปสเตอร์เดิม) · ไอเดีย · เหตุผล · จุดเน้นที่ทำให้ · ความยาว
- สถานะ: กำลังเขียน · ยังไม่ได้เขียน · เขียนไม่สำเร็จ (พร้อมเหตุผลสั้น) · การตัดเปลี่ยนต้องทำใหม่ · รอเรนเดอร์ · กำลังเรนเดอร์ · พร้อม · เรนเดอร์ไม่สำเร็จ · ปิดอยู่
- ปุ่ม: **ทำใหม่** (Claude เขียนชิ้นนี้ใหม่จากไอเดียเดิม) · ลองเรนเดอร์ใหม่ (เมื่อเรนเดอร์ล้มเพราะเครื่อง) · ปิด/เปิด · ลบ
- ไม่มีหน้าแก้ทีละช่องแล้ว (`GraphicSheet` ถูกถอด) · ปุ่ม "แก้" กลับมาใน 0.5.1 เป็นช่องพิมพ์คำสั่ง

คำอธิบายใต้สวิตช์กราฟิกเปลี่ยนเป็น: "AI ออกแบบและเขียนแอนิเมชันเองให้เข้ากับเรื่องที่พูด ต้องติดตั้งตัวเรนเดอร์ในหน้าตั้งค่า และเรียก Claude เพิ่มหนึ่งครั้งต่อชิ้นตอนวางแผน"

แถบแผนระหว่างงานกราฟิก: "กำลังเขียนกราฟิก {done} จาก {total}"

กล่องยืนยันก่อนเขียนและข้อความลอยหลังเขียน นับกราฟิกเหมือนเดิม ชิ้นที่ค้างหรือล้มเหลวนับเป็น "กราฟิกที่ถูกข้าม" · กล่องยืนยันบอกจำนวนชิ้นที่ยังไม่ได้เขียนหรือต้องทำใหม่ และไม่รอชิ้นพวกนี้

## 11. ทดสอบ

- core: ตัวตรวจโค้ด (ทุกข้อของ §6.1 ทั้งที่ต้องผ่านและไม่ผ่าน) · ตัวห่อหน้าเพจ (CSP ตัวแปรเวลา ตัวแปรสี ขนาดเวที ตัวกลาง) · ตัวรับคำตอบรอบวางแผน · ตัวสร้างคำขอรอบเขียนและรอบซ่อม
- main: เรนเดอร์และตรวจภาพด้วยตัวปลอม · วงเขียน ตรวจ ซ่อม หนึ่งรอบ · ทำพร้อมกัน 3 · หยุดกลางทาง · คำพูดเลื่อนและค้าง · ทำใหม่ · การล้างของเก่าและการสำรอง · เขียนลงดราฟต์ข้ามชิ้นที่ค้าง
- หน้าจอ: แถวและสถานะทุกแบบ ปุ่มทำใหม่ แถบแผนบอกจำนวน ไม่มีหน้าแก้แล้ว
- ลองจริงบน 0917 ด้วย Claude จริง: วางแผน เรนเดอร์ เขียนลงดราฟต์ (สำรองก่อน คืนหลัง) ผู้ใช้เปิดใน CapCut และ export ดู

## 12. ความเสี่ยง

- **ช้าและใช้โควตามากขึ้น:** ราว 50 วินาทีต่อชิ้น ทำพร้อมกัน 3 ชิ้น คลิปที่มี 5 ชิ้นเพิ่มราว 2–4 นาที ผู้ใช้รับแล้ว
- **ไฟล์ใหญ่ขึ้น:** ราว 8 MB ต่อวินาทีที่เวทีเกือบเต็มความกว้าง (การ์ดเดิม 5–10 MB ต่อชิ้น)
- **โค้ดจาก Claude รันใน Chrome ของตัวเรนเดอร์:** คำพูดในคลิปอาจมีข้อความที่ชวนให้ Claude เขียนโค้ดแปลก มีสามด่าน (§6.1): ตัวตรวจโค้ด CSP และ Chrome ที่ตัดการเชื่อมต่อออกนอกเครื่อง · ที่เหลือคือคำขอ GET ไปพอร์ตอื่นบนเครื่องเดียวกันหนึ่งครั้ง ถ้าโค้ดเล็ดรอดตัวตรวจ
- **ตัวแปรเวลา (§5.3) ลองแล้วชิ้นเดียว:** ถ้า Claude พิมพ์เลขเวลาของคำลงไปตรง ๆ ตัวตรวจโค้ดจะไม่รู้ ชิ้นนั้นจะไม่เลื่อนตามเมื่อแก้การตัด ต้องดูในการลองจริง
- **อัตราพลาดจริงยังไม่รู้:** 5 จาก 5 ผ่านในการทดลองเรื่องเดียว
- **หน้าตาไม่คงที่ข้ามคลิป:** คุมด้วยกติกาและชุดสี ไม่มีชุดชิ้นส่วนกลางแล้ว
