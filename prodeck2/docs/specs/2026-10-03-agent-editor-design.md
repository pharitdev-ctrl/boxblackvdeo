   │                                     ▲ ผล / ข้อผิดพลาด
② เครื่องมือ: ห่อโมดูลเดิมใน @boxblack/core + เรนเดอร์ตัวอย่าง + ตรวจความถูกต้อง

③ ไทม์ไลน์กลาง: แหล่งความจริงเดียว ทุกการแก้เป็นเวอร์ชันใหม่ ย้อนได้

ขั้นวิเคราะห์ (⓪) และขั้นวางโครงเรื่องไม่เปลี่ยน

### 3.1 จุดเริ่ม: โครงเรื่องที่ยืนยันแล้ว (ผู้ใช้เลือกข้อ 5)

ลำดับของผู้ใช้: วิเคราะห์ → "ให้ AI วางโครงเรื่อง" (หน้าเดิม: ลากสลับ ลบ สั่งแก้) → ยืนยัน → ตัดหยาบ → แท็บ "คุยกับ AI"

- แท็บ "คุยกับ AI" เปิดได้เมื่อมีโครงเรื่องที่ยืนยันแล้วเท่านั้น
- agent ได้รับ: โครงเรื่อง (ชื่อเรื่อง เรื่องย่อ บีต ชื่อ หน้าที่ สิ่งที่ตัดออก) + `cut` จากตัดหยาบ เป็นจุดเริ่มของไทม์ไลน์กลาง
- **โครงเรื่องเป็นของผู้ใช้:** Claude ห้ามเพิ่ม ลบ หรือสลับบีตเอง ถ้าคิดว่าเรื่องควรเปลี่ยน ให้เสนอในแชท (`ask_user`) · ผู้ใช้ตอบตกลง → แอปแก้โครงเรื่องแล้วตัดใหม่ หรือผู้ใช้กลับไปแก้ที่หน้าโครงเรื่องเอง
- ปรับขอบช่วงได้เล็กน้อยโดยไม่ต้องถาม (ข้อ 6 `trim_cut`) เพื่อจังหวะ เช่น ตัดให้ตรงจังหวะเสียง
- ผู้ใช้กลับไปแก้โครงเรื่องหลังตกแต่งแล้ว: ตัดใหม่ · ชิ้นที่ผูกกับคำพูดที่ยังอยู่เลื่อนตาม · ชิ้นที่คำพูดหายถูกถอดออก · แจ้ง Claude ในรอบถัดไป
- เพราะ agent ไม่ได้วางเรื่องเอง prompt วางโครงเรื่องจึงต้องรู้ว่าขั้นตกแต่งทำอะไรได้ (เฟส 1) และ agent ต้องเขียน `direction` จากโครงเรื่องเป็นอย่างแรก

## 4. ไทม์ไลน์กลาง

```ts
interface AgentTimeline {
  projectId: string
  version: number                // เพิ่มทุกครั้งที่มีการแก้ · เก็บทุกเวอร์ชันไว้ย้อน
  direction: string              // แนวทางของคลิปที่ Claude เขียน (อารมณ์ จังหวะ ไฮไลต์ สไตล์) · ผู้ใช้แก้ได้
  cut: Segment[]                 // ช่วงจากคลิปต้นฉบับ เรียงตามลำดับเล่น (ชนิดเดียวกับ rough cut)
  pieces: Piece[]
}

interface Piece {
  id: string
  kind: "move" | "insert" | "text" | "graphic" | "sound" | "subtitle" | "user-other"
  startUs: number; endUs: number // เวลาบนคลิปที่ตัดแล้ว
  spec: unknown                  // ตามชนิด: ใช้ชนิดข้อมูลเดิมของ moves, inserts, highlights, graphics, sounds, subtitles
  by: "claude" | "user"
  locked: boolean                // ชิ้นของผู้ใช้ล็อกเสมอ · Claude แก้/ลบชิ้นที่ล็อกไม่ได้ ต้องขอผู้ใช้
  note: string                   // เหตุผลที่ใส่ · ใช้ตอนติแก้และแสดงให้ผู้ใช้อ่าน
  capcut?: { segmentIds: string[] } // id ของ segment ที่เขียนลง draft ใช้ตอนอ่านกลับ
}
```

- เก็บในโฟลเดอร์ข้อมูลของแอปต่อโปรเจค เหมือนผลงานอื่นของ post plan
- ชิ้นงานของผู้ใช้ที่แอปไม่รู้จัก (เช่น สติกเกอร์ของ CapCut) เป็น `user-other` เก็บ JSON ดิบไว้ เขียนกลับตามเดิมทุก byte

## 5. Agent loop

หนึ่งรอบ (turn) ของ Claude:

1. แอปส่ง: system prompt หลัก + สรุปฟุตเทจ (cache) + ไทม์ไลน์ปัจจุบันเป็นข้อความกระชับ + ประวัติแชท + ผลเครื่องมือของรอบก่อน
2. Claude ตอบเป็น JSON ตาม schema: `{ say?: string, actions: Action[], done: boolean }`
3. แอปทำ actions ทีละตัว ตรวจ (ข้อ 7) แล้วเก็บผลหรือข้อผิดพลาดของแต่ละตัว
4. ถ้า `done` เป็น true หรือไม่มี action → หยุด แสดง `say` ให้ผู้ใช้ รอข้อความถัดไป · ไม่งั้นวนข้อ 1

**ทำไมใช้ JSON actions แทน tool use ของ API:** `LlmTransport.generate()` (`packages/core/src/llm/types.ts`) เป็นแบบถามครั้งเดียวตอบ JSON ตาม zod schema
ใช้ได้ทั้ง Anthropic API และ Claude Code CLI (ซึ่งตอนนี้ปิด tools ทั้งหมดไว้ใน `llm/cli.ts`) โดยไม่ต้องแก้ transport
ข้อเสีย: ส่งบริบทซ้ำทุกรอบ · API ลดด้วย prompt cache · CLI ไม่มี cache ข้ามคำขอ ต้องย่อบริบท (ข้อ 5.2)
ทางเลือกทีหลัง: tool use จริงของ API · หรือ MCP server ของแอปให้ CLI เรียก

### 5.1 งบ (ผู้ใช้เลือก: ไม่จำกัด)

- ไม่มีเพดานต่อคลิป · Claude ทำงานจนเห็นว่าดีแล้วจึงส่ง `done` แล้วผู้ใช้คุยต่อได้ไม่จำกัด
- แต่ต้องมี: ปุ่มหยุดทุกเวลา (ใช้ `stopSignal` แบบเดียวกับ post plan) · แสดงจำนวนรอบ จำนวน token และค่าใช้จ่ายโดยประมาณสด ๆ
- กันวนไม่จบ: **25 รอบต่อหนึ่งข้อความผู้ใช้** (ผู้ใช้เลือก 2026-10-03) · ครบแล้วไม่ตัดจบเฉย ๆ แอปบังคับ Claude สรุปงานที่ทำไปและสิ่งที่ยังค้าง แล้วถามผู้ใช้ "ทำต่อไหม" · กดต่อได้ไม่จำกัด แต่ละครั้งได้อีก 25 รอบ
- ถ้าแก้ชิ้นเดิมกลับไปกลับมา หรือ action ผิดซ้ำหลายรอบติดกัน ให้สรุปส่งผู้ใช้ก่อนครบ 25 รอบได้
- ค่าใช้จ่ายโดยประมาณ (ยังไม่ได้วัด คลิปตัวอย่างฟุตเทจ 10 นาที ตัดเหลือ 1 นาที): ต่อรอบเข้า ~40–50k token (ส่วนใหญ่ cache ได้) ออก ~3–8k · Opus 5.5 ≈ $0.13–0.24 ต่อรอบ · 25 รอบ ≈ $3–6 · วัดค่าจริงจาก `LlmUsage` ในเฟส 3 แล้วปรับ
- ลำดับข้อมูลในคำขอ: ส่วนคงที่ (prompt, ฟุตเทจ) → ประวัติแชท → ไทม์ไลน์ปัจจุบันไว้ท้ายสุด ไม่งั้น cache ของประวัติใช้ไม่ได้ทุกรอบ

### 5.2 บริบท

- สรุปฟุตเทจ: ใช้ `describeFootage()` (`planner/footage.ts`) เป็นฐาน · ส่งเป็น prefix ที่ cache ได้
- ไทม์ไลน์: ส่งฉบับเต็มแบบย่อทุกรอบ (หนึ่งบรรทัดต่อชิ้น) แทนการสะสม diff
- ภาพตัวอย่าง: เก็บเฉพาะของการเรนเดอร์ 2 ครั้งล่าสุด · เก่ากว่านั้นเหลือแค่ข้อความว่าดูอะไรไปแล้ว
- ประวัติแชทยาว: สรุปข้อความเก่าเป็นย่อหน้าเดียวเมื่อเกินขนาดที่ตั้ง

## 7. การตรวจของแอป

ทุก action ตรวจก่อนบันทึก ไม่ผ่าน = ไม่บันทึก ส่งข้อความภาษาไทยบอกเหตุผลกลับให้ Claude:
- เวลาอยู่นอกคลิปที่ตัดแล้ว · อ้างคำพูด/ฉากที่ไม่มี
- กฎซูมเดิม (เพดานตามความละเอียด ±5° ไม่เห็นขอบ หน้าอยู่ในจอ)
- ข้อความ/กราฟิกทับพื้นที่ keepClear หรือหน้าคนหลังซูม
- กราฟิกเรนเดอร์ไม่ผ่าน · เสียงเรนเดอร์ไม่ผ่าน
- แก้ชิ้นที่ล็อก
- เมื่อ cut เปลี่ยน (`trim_cut` หรือผู้ใช้แก้โครงเรื่อง): ชิ้นที่ผูกกับคำพูดเลื่อนตาม · ชิ้นที่คำพูดถูกตัดทิ้งถูกถอดออกและแจ้ง Claude

## 8. เรนเดอร์ตัวอย่าง (ของใหม่ที่ใหญ่ที่สุด)

- ประกอบด้วย ffmpeg ที่ความละเอียดต่ำ (เช่น 540p): ต่อช่วงจาก cut → ซูมด้วย scale/crop ตาม keyframe →
  ซ้อนกราฟิกที่เรนเดอร์แล้ว (ใช้ไฟล์เดียวกับที่ลง CapCut) → ซ้อนข้อความ/ซับที่วาดด้วยหน้า HTML (Playwright) ให้ใกล้สไตล์ของ CapCut
- ส่งให้ Claude เป็น contact sheet ฝังเวลา แบบเดียวกับขั้น vision · เสียงส่งเป็นข้อความ (เสียงอะไร ดังแค่ไหน ตรงไหน)
- แสดงในหน้าแอปให้ผู้ใช้ดูด้วย (เล่นเป็นคลิปพร้อมเสียง)
- **ข้อจำกัด:** หน้าตาใกล้เคียงแต่ไม่ตรงกับ CapCut 100% (ฟอนต์ เอฟเฟกต์ข้อความ) · แสดงคำเตือนในหน้าแอป

## 9. อ่าน draft กลับ (ผู้ใช้เลือกข้อ 1)

เมื่อผู้ใช้เปิดโปรเจคที่เคยส่งออก และ draft ถูกแก้หลังส่งออก (`tm_draft_modified` ใหม่กว่า):

1. `loadDraft()` (`capcut/read.ts`) อ่าน draft
2. จับคู่ segment กับชิ้นงานด้วย `capcut.segmentIds`:
   - เจอและเวลาเปลี่ยน → อัปเดตเวลา · เจอและ spec เปลี่ยน (เช่นแก้คำ) → อัปเดตเท่าที่แปลกลับได้ ที่เหลือเก็บ JSON ดิบ
   - ไม่เจอ (ผู้ใช้ลบ) → ลบชิ้น · จดไว้ว่าผู้ใช้ลบ Claude ห้ามใส่กลับเองโดยไม่ถาม
   - segment ใหม่ที่แอปไม่รู้จัก → `by: "user"`, `locked: true`
3. main track ถูกตัด/ย้าย → แปลงกลับเป็น `cut` ใหม่
4. สรุปการเปลี่ยนแปลงเป็นข้อความส่งให้ Claude ตอนเริ่มรอบถัดไป ("ผู้ใช้ลบเสียง 2 ชิ้น ย้ายข้อความที่ 0:14…")

ส่งออกครั้งถัดไปเขียนทั้งไทม์ไลน์จากไทม์ไลน์กลาง รวมชิ้นของผู้ใช้ (JSON ดิบเดิม) · backup ก่อนเขียนเหมือนเดิม · ต้องปิด CapCut เหมือนเดิม

**ต้องทดลองก่อน (spike):** CapCut ตอน save ทับ (เปิดโปรเจคแล้ว save ทันที เพิ่ม field ใหม่) ยังคง segment id เดิมไหม · ถ้าไม่ ต้องจับคู่ด้วย material path + เวลา

## 10. หน้าจอ

- แท็บใหม่ "คุยกับ AI" ข้างโหมดเดิม
- ซ้าย: แชท (ข้อความ Claude, action ที่ทำเป็นบรรทัดย่อกดดูได้, ปุ่มหยุด, ตัวนับรอบ/ค่าใช้จ่าย)
- ขวาบน: ตัวอย่างคลิปล่าสุด · ขวาล่าง: รายการชิ้นงานตามเวลา (ลบ ล็อก "ให้ AI แก้ชิ้นนี้" ย้อนเวอร์ชัน)
- ปุ่ม "เขียนลง CapCut" ใช้ขั้นตอนเดิม (ตรวจ CapCut ปิด → backup → เขียน)

## 11. ไฟล์ที่เกี่ยวข้อง

ใหม่:
- `packages/core/src/agent/` · timeline.ts (ชนิดข้อมูล + ตรวจ) · actions.ts (schema + ตัวทำ) · prompt.ts · context.ts (ย่อบริบท)
- `packages/core/src/preview/` · ประกอบตัวอย่างด้วย ffmpeg + วาดข้อความ
- `packages/core/src/capcut/reconcile.ts` · อ่าน draft กลับ
- `apps/desktop/src/main/agent.ts` · loop, หยุด, เก็บเวอร์ชัน, ส่ง event
- `apps/desktop/src/renderer/…` · แท็บ "คุยกับ AI"

แก้:

## 13. ความเสี่ยง

- **ค่าใช้จ่าย:** ไม่จำกัดงบตามที่ผู้ใช้เลือก แต่คลิปยาว + ภาพตัวอย่างหลายรอบอาจแพงกว่า "ทำทั้งหมด" หลายเท่า · ต้องแสดงตัวเลขให้ผู้ใช้เห็นเสมอ
- **Claude Code CLI:** ไม่มี prompt cache ข้ามคำขอ ช้าและเปลืองกว่า API ในโหมดนี้ · อาจติดโควต้าของผู้ใช้
- **ผลไม่เหมือนเดิมทุกครั้ง:** ต่างจาก pipeline ที่คาดเดาได้กว่า
- **ตัวอย่างไม่ตรง CapCut:** Claude อาจปรับตามภาพที่ไม่ตรงกับของจริง
- **อ่านกลับ:** CapCut เปลี่ยนรูปแบบ draft ระหว่างเวอร์ชัน (มีบทเรียนจาก 9.2 → 9.4 → 9.5)
- **license server จ่าย prompt:** prompt หลักของ agent ต้องจ่ายผ่าน server ได้เหมือน prompt อื่น (`SystemPrompt.version`)
