# M15 · สื่อแทรก: เลือกจุดจากรูปจริง และวางไม่ให้ทับทั้งจอ — design

วันที่ 2026-09-22 · ต่อจาก M10.4 (สื่อแทรก) และ M12 (สื่อแทรกตามคำพูด)

## 1. ปัญหาจากการใช้จริง

ผู้ใช้ทดสอบแล้วพบสองเรื่อง

1. **จุดที่วางไม่เข้ากับบริบท** — ตอนเลือกว่าประโยคไหนคู่กับรูปไหน Claude เห็นแค่**คำบรรยายหนึ่งบรรทัด**
   ที่ prompt `media-2026-09-18` สั่งไว้ว่า "สั้นที่สุด" และ "ไม่ต้องบรรยายสี แสง หรืออารมณ์" · รูปจริงไม่ได้ถูกส่งไปในการเลือกจุด ·
   คลิปยังถูกดูแค่เฟรมกลางเฟรมเดียว จึงพลาดของที่โผล่ต้นหรือท้ายคลิป
2. **รูปทับเต็มจอ** — ตอนเขียน `coverScale` ขยายรูปให้เต็มเฟรมเสมอ คนพูดหายไปตลอด 2 วินาที
   และพื้นหลังรอบตัวของในรูปกลายเป็นทั้งจอ

เรื่องคัตเอาต์พื้นหลังจริงๆ ต้องมี alpha channel ซึ่งต้องสร้างไฟล์ใหม่ด้วยโมเดล segmentation — อยู่นอกขอบเขต ·
สิ่งที่ทำได้และได้ผลใกล้กันคือ **ครอปให้ชิดตัวของ** และ **ไม่ต้องกินทั้งจอ**

## 2. สิ่งที่ผู้ใช้เลือก

- หน้าตาของรูปที่แทรก: **ทั้งสองแบบ แล้วแต่ลักษณะของสิ่งที่อินเสิร์ท** → AI ตัดสินต่อรูปตอนที่ดูรูปนั้น
- จุดที่ไม่เข้ากับบริบท: **ให้ AI เห็นรูปจริงตอนเลือกจุด**

## 3. ตอนดูรูป (`flair/look-at.ts`) — ตอบมากขึ้นต่อรูป

```ts
{ picture: number; what: string; subject: number[]; fit: "cover" | "card" }
```

- `what` — 1–2 ประโยค: สิ่งที่เห็น สี ลาย ที่ทางรอบๆ และคำที่คนน่าจะพูดถึงรูปนี้ (เลิกสั่ง "สั้นที่สุด/ไม่ต้องบอกสี")
- `subject` — กรอบของตัวของในรูป `[x0, y0, x1, y1]` เป็นสัดส่วนของกว้าง/สูง · ตอบ `[]` เมื่อของเต็มเฟรมอยู่แล้วหรือชี้ไม่ได้
  (รูปแบบเดียวกับ `keepClear` ของวิดีโอ: ค่าที่ไม่ครบ 4 หรือกลับด้านถูกทิ้ง)
- `fit` — `cover` เมื่อของกินเฟรมเกือบหมดหรือรายละเอียดคือประเด็น (โคลสอัปสินค้า ภาพหน้าจอ) ·
  `card` เมื่อมีที่ว่างรอบตัวของมาก เป็นภาพกว้าง หรือควรเห็นคนพูดไปด้วย · ค่าเริ่มต้นเมื่อไม่ตอบ = `card`
- **คลิปดู 3 เฟรม** (ต้น กลาง ท้าย) แทนเฟรมเดียว · รูปนิ่งยังเฟรมเดียว
- `MEDIA_PROMPT_VERSION` = `media-2026-09-22-framing` (เวอร์ชันเปลี่ยน = คำบรรยายเดิมถูกถามใหม่ครั้งเดียว)

## 4. ตอนเลือกจุด (`flair/direct.ts`) — ส่งรูปจริงไปด้วย

คำขอจัดลูกเล่นแนบ**ภาพของทุกรูปที่แทรกได้** ต่อท้ายรายการ (`รูปที่ 1` + ภาพ) คู่กับคำบรรยายและรายการประโยค ·
Claude จึงเลือกจุดจากรูปที่เห็นจริง ไม่ใช่จากคำบรรยายของตัวเอง · `FLAIR_PROMPT_VERSION` = `flair-2026-09-22-see-pictures`

ราคา: ~1.5k token ต่อรูปต่อครั้งที่กด "จัดลูกเล่น" (โปรเจกต์ที่มี 2–5 รูป = 3–8k) · ส่งเฉพาะตอนสื่อแทรกเปิดและมีรูป

## 5. ตอนเขียน (`capcut/inserts.ts`) — สองหน้าตา

`TimelineInsert` เพิ่ม `fit`, `subject` และ `keepClear` (แถบห้ามบังของฉากที่เล่นตรงนั้น)

- **cover** — ครอปให้ชิดตัวของ: ขยายจากกรอบ `subject` ให้กรอบนั้นเต็มเฟรม แล้วเลื่อน `transform` ให้จุดกึ่งกลางของกรอบ
  อยู่กลางจอ · เพดานการขยาย 2.5 เท่าของ cover เดิม (กันรูปแตกเมื่อของเล็กมาก) · ไม่มี `subject` = เหมือนเดิม
- **card** — รูปกว้าง 62% ของจอ วางในแถบที่ว่างที่สุดเทียบกับ `keepClear` ของฉากนั้น (เหนือหรือใต้แถบ แล้วแต่ที่ไหนกว้างกว่า ·
  ไม่มีข้อมูลภาพ = วางกลางค่อนล่าง y = −0.35 ซึ่งยังพ้นซับที่ −0.8) · การ์ดสูงเกินแถบก็ยังอยู่ในจอ ไม่ล้นขอบ
  - **ไม่มีขอบ/เงารอบการ์ด**: ขอบต้องเป็น `shapes` ซึ่ง CapCut วาดโตกว่าที่สั่ง 1.5 เท่าบนจอแนวตั้ง และบนจอแนวนอนยังไม่ได้วัด
    (เหตุผลเดียวกับที่แถบสีหลังข้อความเป็น portrait-only) · เลี่ยงกลไกที่ยังไม่ได้พิสูจน์ไว้ก่อน

ทั้งสองแบบยังปิดเสียงคลิป และอยู่ใต้ข้อความเด่นกับซับเหมือนเดิม

## 6. ในแอป

- `InsertView` เพิ่ม `fit` · แท็บลูกเล่นและป้ายในแถวคำพูดบอกว่า "การ์ด" หรือ "เต็มจอ" และ**สลับเองได้**
  (`setInsert` เดิมรับ `fit` เพิ่มได้: `setInsert(folder, anchor, binId, fit?)` — ตั้งเองแล้ว Claude ไม่แตะ)
- ไม่เพิ่มสวิตช์ระดับคลิป: หน้าตาเป็นเรื่องของรูปแต่ละรูป

## 7. ไม่อยู่ในขอบเขต

คัตเอาต์พื้นหลังจริง (ต้อง alpha) · ขอบมน/เงาของการ์ด (ต้อง mask ซึ่งยังไม่ได้พิสูจน์กับ CapCut 9.4) ·
แอนิเมชันเข้า/ออกของรูป · หลายรูปพร้อมกัน

สิ่งที่เปลี่ยนจากแผนระหว่างทาง

- `framing.ts` แยกออกมาเป็นไฟล์ของตัวเอง (คณิตศาสตร์ล้วน ไม่รู้จัก draft) แล้ว `inserts.ts` เรียกใช้ · `coverScale` ย้ายมาที่นี่และ re-export ไว้
- **ไม่มีขอบ/เงาของการ์ด** ตามที่ตัดออกในข้อ 5: `shapes` ถูกวาดโตกว่าที่สั่ง 1.5 เท่าและบนจอแนวนอนยังไม่ได้วัด
- `InsertCue` เก็บ `fit`/`subject` ไว้เอง เพื่อให้ preview กับ write เห็นตรงกันเสมอ (timeline ไม่มี cache คำบรรยาย) ·
  ตอนผู้ใช้เลือกรูปเอง `flair.setInsert` ไปอ่าน look จาก cache มาเติมให้ ถ้าอ่านไม่ได้ก็เป็น `cover`
- `keepClearAt(plan, clips, atUs)` หาแถบห้ามบังของฉากที่เล่นตรงนั้น โดยไล่จากเวลาบน timeline กลับไปเป็นเวลาในไฟล์ต้นทาง

**ทดสอบจริงบน 0917** (ใส่รูปเล็บ 2 รูปชั่วคราว สำรองและคืนทั้ง draft และกรุสื่อแล้ว)

- คำบรรยายรูปละเอียดขึ้นจริง: *"มือซ้ายทำเล็บยาวทรงบัลเลริน่าสีชมพูนู้ดใส มีลายเขียนมือเล็กๆ เช่น เส้นโค้งสีเหลือง รูปหัวใจสีเหลือง จุดสีแดง ดาวสีน้ำเงิน และดอกไม้สีขาว วางอยู่หน้าท่อ…"* เทียบกับของเดิมที่ได้แค่ *"เล็บยาวสีชมพูสลับฟ้า ลายกากบาท วางบนเครื่องอบเล็บ"*
- สั่ง "จัดลูกเล่น" โดยแนบรูปจริงไปด้วย → Claude **ไม่แทรกเลย** เพราะคลิปพูดเรื่องนักบินอวกาศ (พฤติกรรมที่ต้องการ)
- เลือกรูปเองที่ประโยคแรก → ได้ `fit` ของรูปนั้นเองคือ **เต็มจอ** (โคลสอัปเล็บ) · กดสลับเป็น **การ์ด** ได้
- เขียนจริงแล้วอ่าน `draft_info.json` กลับ: overlay track มี `scale 0.62`, `transform { x: 0, y: −0.535 }` — การ์ดกว้าง 62% ของจอ
  วางในแถบใต้แถบห้ามบังของฉากนั้น ไม่ทับหน้า และไม่กินทั้งจออีกต่อไป

ข้อจำกัดที่รู้: ยังไม่ได้เปิดดูใน CapCut (ผู้ใช้ดูเอง) · การครอปชิดของพิสูจน์แล้วด้วยเลขแต่ยังไม่ได้เห็นกับรูปจริงที่ AI วางเอง
เพราะรูปทดสอบไม่เข้ากับเนื้อหาคลิป · ยังไม่มีคัตเอาต์พื้นหลังจริง

## 9. ทดสอบ

look-at: `subject`/`fit` ที่ผิดรูปแบบถูกทิ้ง · คลิปได้ 3 เฟรม · prompt บอกกฎใหม่ ·
direct: ภาพถูกแนบไปกับคำขอเมื่อมีรูป และไม่แนบเมื่อไม่มี ·
inserts (writer): cover ครอปตาม subject และเลื่อนให้อยู่กลาง · เพดานการขยาย · card ได้ขนาด ตำแหน่งตาม keepClear และมีขอบขาวหลังรูป ·
main: `fit` เดินทางจากคำบรรยายถึงตัวเขียน · ผู้ใช้สลับ fit เองแล้วอยู่คงทน ·
renderer: ป้ายและปุ่มสลับ · mutation check ทุกไฟล์ · เขียน 0917 จริงแล้วอ่าน JSON กลับ
