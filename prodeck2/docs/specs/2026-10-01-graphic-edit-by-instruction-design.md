# สั่งแก้กราฟิกด้วยข้อความ (0.5.1)

- สถานะ: ออกแบบแล้ว ผู้ใช้อนุมัติแนวทาง 2026-10-01 รอผู้ใช้อ่านสเปก
- ต่อจาก: `docs/specs/2026-09-30-freeform-motion-design.md` (0.5.0) §13
- ขอบเขต: เฉพาะการสั่งแก้ด้วยข้อความ ผู้ใช้ไม่เอาพรีวิวที่เล่นได้

## 1. สิ่งที่ผู้ใช้เลือก (2026-10-01)

| เรื่อง | ที่เลือก |
|---|---|
| สิ่งที่เพิ่มใน 0.5.1 | สั่งแก้กราฟิกด้วยข้อความอย่างเดียว ไม่มีพรีวิวที่เล่นได้ |
| ย้อนกลับ | ย้อนได้หนึ่งขั้น |
| AI คิดใหม่ | แทนที่ชิ้นที่สั่งแก้ได้ การสั่งแก้ไม่ทำให้ชิ้นนั้นเป็นของผู้ใช้ (เหมือนปุ่มทำใหม่) |
| แนวทาง | ส่งโค้ดเดิม คำสั่ง และโจทย์เดิมให้ Claude เขียนชิ้นใหม่ทั้งชิ้น ผ่านวงเขียน ตรวจ ซ่อม ของ 0.5.0 |

## 2. หน้าจอ

- แถวกราฟิกที่มีโค้ดแล้ว (เขียนแล้ว รวมชิ้นที่ "การตัดช่วงนี้เปลี่ยนไป") มีปุ่ม **"แก้"** ต่อจาก "ทำใหม่" · ชิ้นที่ยังไม่ได้เขียนหรือเขียนไม่สำเร็จไม่มีปุ่มนี้ ใช้ "ทำใหม่"
- กด "แก้" แล้วมีช่องพิมพ์ใต้แถว พร้อมปุ่ม **"ส่งให้ AI แก้"** และ **"ยกเลิก"** หน้าตาแบบช่องแก้โครงเรื่อง · ส่งได้เมื่อพิมพ์แล้ว ยาวไม่เกิน 300 ตัวอักษร (นับแบบ grapheme)
- ระหว่างแก้ แถวนั้นขึ้น **"กำลังแก้…"** แถบแผนขึ้นเหมือนตอนทำใหม่ ("กำลังเขียนกราฟิก 0 จาก 1") ปุ่มแก้และทำใหม่ทุกแถวกดไม่ได้จนจบ
- แถวแสดงคำสั่งล่าสุดใต้ไอเดีย: **"แก้ล่าสุด: <คำสั่ง>"** (สองบรรทัด ที่เหลืออยู่ใน title)
- แก้ไม่สำเร็จ: ชิ้นเดิมใช้ต่อได้ แถวมีบรรทัดเตือน **"แก้ไม่สำเร็จ · <เหตุผลบรรทัดท้าย>"** ใต้สถานะ จนกว่าจะแก้ ทำใหม่ หรือย้อน
- มีชิ้นก่อนหน้าเก็บไว้: แถวมีปุ่ม **"ย้อน"** สลับไปชิ้นก่อนหน้า กดอีกครั้งสลับกลับ ไม่เรียก Claude
- ข้อความทั้งหมดอยู่ใน `i18n.ts`

## 3. การทำงาน

**การแก้เป็นงานหนึ่งรอบ** แบบเดียวกับ `redoGraphic`: งาน "กราฟิก" รอบเดียว ห้ามซ้อนกับรอบอื่นของโปรเจกต์ กดหยุดได้ทุกช่วง ความคืบหน้า (0, 1) แล้ว (1, 1)

**หาชิ้น** จากชิ้นที่วางอยู่ เล่นอยู่หรือปิดอยู่ ด้วย anchor เหมือนทำใหม่ · ไม่มีที่บนคลิปตอนนี้ → งานล้มด้วยข้อความเดียวกับทำใหม่ · ไม่มีโค้ด → งานล้มด้วย `this graphic has not been written yet` (มีคำไทยใน `MAIN_WORDS`)

**เขียนสำหรับที่ว่างจริงตอนนี้** เหมือนทำใหม่: ความยาวที่เล่นได้ คำพูดพร้อมเวลาตอนนี้ ขนาดเวทีจากกรอบที่วางจริง · ชิ้นที่ต้องทำใหม่จึงหายค้างไปพร้อมการแก้

**โจทย์ที่ส่ง Claude** (ภาษาอังกฤษแบบเดียวกับโจทย์ซ่อม ฟังก์ชันใหม่ `editBrief` ใน `motion/write.ts`): โจทย์แรกตามที่ว่างตอนนี้ (`motionBrief`) บรรทัดว่าง `You wrote the fragment below for this brief. The user asks for this change:` คำสั่งของผู้ใช้ในเครื่องหมายคำพูด บรรทัดว่าง `Make that change and keep everything else as it is, unless the brief above has changed (the length, the words and their times, the stage): then fit the fragment to the brief as it is now. Return the whole fragment, with no code fence and no explanation.` บรรทัดว่าง แล้วโค้ดเดิม · ใช้กติกา (`MOTION_CONTRACT`) เดิม

**ตรวจและซ่อม** ด้วย `writePiece` ของ 0.5.0 ที่รับโจทย์แรกจากภายนอกได้: ตรวจโค้ด เรนเดอร์ตรวจ ซ่อมได้หนึ่งรอบ (โจทย์ซ่อมพาโจทย์แก้ไปทั้งก้อน) · เครื่องเรนเดอร์ไม่ได้ → ใช้โค้ดที่ผ่านตัวตรวจ

**เก็บผล** ในการบันทึกครั้งเดียวต่อชิ้น เหมือนทำใหม่:
- สำเร็จ: `html` `seconds` `words` `version` ใหม่ · `instruction` = คำสั่ง · `previous` = ชิ้นก่อนแก้ (`html` `seconds` `words` `version` `instruction` ของมัน) · ลบ `editFailed` และ `failed`
- ไม่สำเร็จ: ชิ้นเดิมไม่เปลี่ยน · `editFailed` = เหตุผล (สามบรรทัดแรกของปัญหาครั้งสุดท้าย หรือข้อความของการเรียกที่ล้ม)
- หยุดกลางทาง: ไม่เก็บอะไร
- ไม่ทำให้ชิ้นเป็นของผู้ใช้ (`edited` ไม่เปลี่ยน) ไม่แตะชิ้นอื่น

**ทำใหม่ก็เก็บชิ้นก่อนหน้า** เพื่อให้สองปุ่มทำงานแบบเดียวกัน: ทำใหม่ครั้งใดที่ชิ้นเดิมมีโค้ด `previous` = ชิ้นเดิม ทั้งตอนสำเร็จและตอนล้ม (ล้มแล้ว `html` เป็น null ตามเดิม แต่ย้อนกลับไปชิ้นที่ใช้ได้ได้) · ทำใหม่ลบ `instruction` · ข้อจำกัดของ 0.5.0 "ทำใหม่ที่ล้มทำให้ชิ้นที่ใช้ได้หายไป" จึงหายไปด้วย

**ย้อน** (`undoGraphic(folder, anchor)`): สลับชิ้นปัจจุบันกับ `previous` ในการบันทึกครั้งเดียว ไม่ใช่งานของรอบวางแผน ไม่เรียก Claude · ชิ้นปัจจุบันที่ไม่มีโค้ด (ทำใหม่ล้ม) เมื่อสลับแล้ว `previous` ว่าง ปุ่มย้อนหายไป · ลบ `editFailed` · ไฟล์เรนเดอร์ของชิ้นก่อนหน้ายังอยู่ตาม hash จึงไม่ต้องเรนเดอร์ใหม่ ถ้าที่ว่างตอนนี้ต่างจากตอนเขียนชิ้นนั้น ชิ้นนั้นเป็น "การตัดช่วงนี้เปลี่ยนไป" ตามกติกาเดิม · ห้ามระหว่างมีรอบวางแผนของโปรเจกต์ทำงานอยู่

**AI คิดใหม่** แทนที่ชิ้นที่สั่งแก้ได้ตามปกติ พร้อม `previous` ของมัน

## 4. ข้อมูล

`MotionSpec` เพิ่มฟิลด์ที่ไม่บังคับ:

- `instruction?: string` คำสั่งที่ทำให้เกิดโค้ดปัจจุบัน
- `editFailed?: string` เหตุผลที่การแก้ครั้งล่าสุดไม่สำเร็จ (มีโค้ดเดิมอยู่)
- `previous?: { html: string; seconds: number; words: MotionWord[]; version: string; instruction?: string }`

`GraphicView` เพิ่ม `instruction: string | null`, `editFailed: string | null`, `canUndo: boolean` · `DesktopApi` เพิ่ม `editGraphic(folder, anchor, instruction, request): Promise<PostRunView>` และ `undoGraphic(folder, anchor): Promise<void>` · ทั้งสองอยู่ใน `API_METHODS` และ `editGraphic` อยู่ใน `LICENSED_METHODS` · `highlight-api.ts` ตรวจอาร์กิวเมนต์ (คำสั่งเป็นข้อความ ไม่ว่าง ไม่เกิน 300)

โปรเจกต์ของ 0.5.0 อ่านได้ตามเดิม ฟิลด์ใหม่ไม่มีก็คือไม่มี ไม่ต้องล้างข้อมูล · ขนาดไฟล์แผนโตขึ้นได้ถึงโค้ดหนึ่งชิ้นต่อกราฟิก (ไม่เกิน 40,000 ตัวอักษร)

## 5. ทดสอบ

- core: `editBrief` ตามรูปแบบ · `writePiece` รับโจทย์แรกจากภายนอก
- main: แก้สำเร็จเก็บครบ · แก้ล้มชิ้นเดิมอยู่และมี `editFailed` · หยุดไม่เก็บ · ชิ้นไม่มีโค้ดหรือไม่มีที่ล้มด้วยข้อความ · ทำใหม่เก็บ `previous` ทั้งสำเร็จและล้ม · ย้อนสลับและกดซ้ำสลับกลับ · ย้อนระหว่างมีรอบทำงานถูกปฏิเสธ · AI คิดใหม่แทนที่ · ไลเซนส์ · อาร์กิวเมนต์
- renderer: ปุ่ม แก้/ย้อน ขึ้นเมื่อใด · ช่องพิมพ์ ส่ง ยกเลิก จำกัดความยาว · "กำลังแก้…" เฉพาะแถวนั้น · "แก้ล่าสุด" · บรรทัดแก้ไม่สำเร็จ · ปุ่มทุกแถวกดไม่ได้ระหว่างรอบ
- controller: mutation ส่วนใหม่ · ลองจริงกับ Claude บนโปรไฟล์ทดสอบ (แก้ 3 แบบ: ขนาด ทิศทาง ความเร็ว · ย้อน · แก้ชิ้นที่ต้องทำใหม่) · เขียนลง 0917 ให้ผู้ใช้เปิดดู แล้วคืน

## 6. ข้อจำกัดที่รู้

- การแก้ใช้เวลาราว 30 ถึง 40 วินาที เท่าเขียนหนึ่งชิ้น
- ย้อนได้ขั้นเดียว แก้สองครั้งติด ชิ้นก่อนการแก้ครั้งแรกหายไป
- Claude อาจตีความคำสั่งกว้างเกิน ผู้ใช้ย้อนแล้วสั่งใหม่ให้ชัดขึ้นได้
