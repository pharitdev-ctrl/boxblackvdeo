# BOXBLACK — ออกแบบ UI/UX ใหม่ (design)

วันที่: 2026-09-18 · สถานะ: ผู้ใช้อนุมัติแบบแล้ว · ต่อยอดจาก `2026-09-17-capcut-timeline-manager-design.md`

## 1. ปัญหาที่แก้

ผู้ใช้ทดลองใช้แอปจริงแล้วระบุปัญหา 4 ข้อ เรียงตามความหนัก:

1. **หน้า timeline ยาว หาไม่เจอ** — ทุกอย่าง (กติกาการตัด, ซับ, ข้อความเด่น, ลูกเล่น 3 ชนิด, รายการบีต, สำรอง) เรียงต่อกันเป็นหน้าเดียวยาวมาก ต้องเลื่อนหาตลอด
2. **ไม่เห็นภาพผลลัพธ์** — ไม่รู้ว่าลูกเล่นแต่ละอย่างไปอยู่ตรงไหนของคลิป
3. **ขั้นตอนเยอะ กดหลายหน้า** — sidebar 5 ขั้น เดินหน้า-ถอยหลังบ่อย
4. **หน้าตาดูดิบ ไม่น่าขาย**

ขอบเขตงานนี้คือ **renderer เท่านั้น** ไม่แตะ pipeline, ตัวเขียน draft, หรือ prompt ใด ๆ ฝั่ง main process แก้เฉพาะสองอย่างเล็ก ๆ ที่ระบุไว้ในข้อ 5

## 3. หน้าจอ

### 3.1 เปลือกแอป

แถบบนสูง 48px แถบเดียว ไล่จากซ้าย: `‹ โปรเจกต์` · ชื่อโปรเจกต์ · ป้ายระยะ `1 เตรียม › 2 โครงเรื่อง › 3 ตัดต่อ` (ระยะที่ผ่านแล้วเป็น ✓ สีเขียว กดย้อนได้ · ระยะที่ยังไม่ถึงกดไม่ได้) · ด้านขวา: ปุ่มเฉพาะระยะ, `สำรอง · N`, ปุ่มหลักของระยะนั้น

แถบเตือนอยู่ใต้แถบบน ครั้งละหนึ่งบรรทัด เรียงลำดับความสำคัญ: license ใกล้หมด/ออฟไลน์ > CapCut เปิดอยู่ > อัปเดตพร้อมติดตั้ง > คำเตือนของโปรเจกต์ (ไฟล์หาย / เวอร์ชันไม่เคยทดสอบ / timeline มีของ) ที่เหลือพับเป็น "ดูทั้งหมด (N)"

หน้าต่างยังใช้ `titleBarStyle: hiddenInset` + vibrancy เหมือนเดิม แต่ vibrancy ย้ายจาก sidebar (ที่ถูกลบ) มาเป็นพื้นแถบบน

### 3.2 ระยะ 1 · เตรียม

**หน้าเลือกโปรเจกต์** — การ์ดปก **อัตราส่วน 9:16 จริง** (ของเดิมเป็นจัตุรัสมีแถบดำ) มีความยาวคลิปมุมล่างขวา · ช่องค้นหาชื่อบนแถบบน · เรียงตามแก้ล่าสุด

**หน้าโปรเจกต์** — รายการวิดีโอติ๊กเลือก (ชื่อ · ความยาว · ความละเอียด) · ท้ายจอแสดงจำนวนที่เลือกและประมาณการ token + ปุ่ม `เริ่มวิเคราะห์`

กดเริ่มแล้ว **ไม่เปลี่ยนหน้า**: แต่ละแถวขึ้นแถบความคืบหน้าสองเส้น (เสียง / ภาพ) พร้อมข้อความสถานะ เสร็จแล้วเป็นสีเขียว · ปุ่มท้ายแถว `ดู` เปิดคำพูดกับฉากที่ได้ (popover) · วิดีโอที่ไฟล์หายแสดงจาง ขีดฆ่า ติ๊กไม่ได้ · ปุ่มท้ายจอเปลี่ยนเป็น `ยกเลิก` ระหว่างทำ และเป็น `ไปโครงเรื่อง ›` เมื่อครบ

ถ้าเครื่องยังไม่พร้อม (ffmpeg/whisper/model/key ขาด) แสดงกล่องบอกว่าขาดอะไรพร้อมปุ่มไปตั้งค่า แทนที่รายการ

### 3.3 ระยะ 2 · โครงเรื่อง

สองคอลัมน์:

- **ซ้าย 300px — โจทย์**: ความยาวเป้าหมาย (segmented), ประเภทคลิป (select), คำสั่งเพิ่มเติม (textarea), ปุ่ม `ให้ AI วางโครงเรื่อง` (เปลี่ยนเป็น `↻ วางโครงเรื่องใหม่` เมื่อมีโครงแล้ว), เส้นคั่น, ช่อง `สั่งแก้โครงเรื่องที่มีอยู่` + ปุ่มส่ง, บรรทัดเล็กบอกว่าวางเมื่อไหร่ด้วยโมเดลอะไร
- **ขวา — โครงเรื่อง**: ชื่อเรื่อง, สรุป, สิ่งที่ตัดออก, ป้ายความยาวรวม/เป้า, รายการบีตเป็นการ์ด (มือจับลาก ⋮⋮ · thumbnail 9:16 · ชื่อ · จุดประสงค์ · คลิป+ช่วงเวลา · คำพูด/คำบรรยายภาพ · ปุ่ม ▶ ✕), แถบพับ "ส่วนที่ AI ไม่ได้ใช้ · N ส่วน"

**ลากสลับลำดับ**: ใช้ HTML5 drag-and-drop ธรรมดา (`draggable` + `dragover` + `drop`) ไม่เพิ่ม dependency · ปล่อยแล้วเรียกลำดับใหม่ผ่าน `saveOutlineEdits` เดิม · เข้าถึงด้วยคีย์บอร์ดได้ด้วยปุ่ม ↑ ↓ ที่ยังอยู่ (ซ่อนไว้จนโฟกัส)

ระหว่าง AI คิด: การ์ดเดิมจางลง มีแถบสถานะ + ปุ่มยกเลิก ไม่ใช่หน้าว่าง

ปุ่มท้ายจอ `ยืนยันโครงเรื่อง ›`

### 3.4 ระยะ 3 · ห้องตัดต่อ

สองคอลัมน์ ไม่มีพรีวิว ไม่มีแถบเวลา

**ซ้าย 268px — รายการบีต**: การ์ดบีต (แถบสีประจำบีต · ชื่อ · ความยาวก่อน→หลังตัด · ป้ายนับลูกเล่น `Aa 2` `🔊 1` `⤢ 1` `🖼 1`) · ด้านล่าง: ความยาวรวม/เป้า/จำนวนชิ้น, ลิงก์ `‹ แก้โครงเรื่อง`, ลิงก์สำรอง

**ขวา — บีตที่เลือก**: หัวเรื่อง (ชื่อบีต · ไฟล์ · ก่อน→หลัง · จำนวนชิ้น) แล้วแท็บ 4 แท็บพร้อมจำนวนในวงเล็บ

| แท็บ | เนื้อหา |
|---|---|
| **คำพูด** | แถวละประโยค: ป้าย (ใช้ / ตัด·เหตุผล / เก็บ) · ช่วงเวลา · ข้อความ · ปุ่มที่โผล่ตอนชี้เมาส์ (▶ เล่นในบริบท, `Aa เน้น` ทำเป็นข้อความเด่น, `ตัด`/`เก็บ`) · ช่วงเงียบพับเป็นบรรทัดเดียว |
| **ข้อความเด่น** | ชุดละกล่อง: ช่วงเวลา · ป้าย AI/คุณ · คำอธิบายการวาง · ปุ่ม `⚙︎ รูปลักษณ์` (popover: รูปแบบ, คำเน้นสี, ตอนหายไป) และ `ลบชุด` · บรรทัดข้อความแก้ได้ในช่อง |
| **ซับ** | บรรทัดละช่องแก้ข้อความ + เวลา · ปุ่ม `✦ เกลาด้วย AI` ถ้าเปิดไว้ |
| **ลูกเล่น** | รายการจุดของบีตนี้ สองกลุ่ม: **เสียงประกอบ/สื่อแทรก** เรียงตามเวลา (เวลา · จุดนั้นคืออะไร · select) และ **ซูมภาพ** รายชิ้นวิดีโอ (เวลา · ประโยคในชิ้น · ความยาว · select) |

แท็บที่ถูกปิดจากตั้งค่า (เช่นซับปิดอยู่) แสดงเป็นแท็บจาง กดแล้วบอกว่าปิดอยู่ พร้อมปุ่มเปิด

**ปุ่มบนแถบบนของระยะนี้**: `⚙︎ ตั้งค่าคลิป` (แผ่น 4 แท็บ), `✦ ให้ AI แต่ง ▾` (เมนู: เลือกข้อความเด่น / จัดลูกเล่น / เกลาซับ), `เขียนลง CapCut`

**เขียน**: กดแล้วขึ้นแผ่นยืนยันสรุปทุกอย่างที่จะเขียน (จำนวนชิ้น, ความยาว, แทนที่กี่ชิ้น, ซับ, ข้อความเด่น, เสียง, ซูม, สื่อแทรก) + บรรทัดบอกว่าสำรองให้เสมอ · เสร็จแล้วขึ้น toast ด้านล่าง ปุ่มบนเปลี่ยนเป็น `เขียนอีกครั้ง` · CapCut เปิดอยู่ = ปุ่มเทาและมีแถบเตือน

**ระหว่างคำนวณใหม่** (เปลี่ยนกติกา/ตั้งค่า): เนื้อหาเดิมจางลงพร้อม skeleton ไม่หายไปเป็นข้อความ "กำลังคำนวณ"

### 3.5 ตั้งค่า

หน้าตั้งค่าเดิม (การถอดเสียง, license, เครื่องมือ, Claude) คงเนื้อหาไว้ เพิ่มหัวข้อ **หน้าตา** ที่มีตัวเลือก ตามระบบ / สว่าง / มืด และจัดหน้าใหม่ให้ใช้ชิ้นส่วน UI ชุดเดียวกับหน้าอื่น

## 4. โครงไฟล์ renderer

ปัจจุบัน renderer มี 3,046 บรรทัดใน 7 screen + 12 component และ CSS ก้อนเดียว 1,436 บรรทัด งานนี้จัดใหม่เป็น:

```
src/
  App.tsx                 เลือกว่าจะแสดง shell ไหน (activation / งาน / ตั้งค่า)
  shell/
    AppShell.tsx          แถบบน + ป้ายระยะ + แถบเตือน + ช่องใส่ปุ่มของระยะ
    StageChips.tsx        ป้าย 3 ระยะ กดย้อนได้
    AlertBar.tsx          จัดลำดับและพับคำเตือน
    BackupMenu.tsx        ปุ่ม + popover สำรอง/กู้คืน   (จาก BackupList.tsx)
  ui/                     ชิ้นส่วนกลาง ไม่มีความรู้เรื่องงาน
    Button.tsx  Segmented.tsx  Select.tsx  Switch.tsx  Field.tsx
    Sheet.tsx   Popover.tsx    Toast.tsx   Progress.tsx  Tabs.tsx  Empty.tsx
  screens/
    ActivationScreen.tsx        (คงเดิม จัดหน้าใหม่)
    ProjectsScreen.tsx          (จาก ProjectListScreen)
    PrepareScreen.tsx           (รวม ProjectDetailScreen + AnalyzeScreen)
    OutlineScreen.tsx           (รวม brief + beats + ลาก)
    EditScreen.tsx              (จาก TimelineScreen — เหลือแค่ประกอบร่างและ state)
    SettingsScreen.tsx          (คงเดิม + หัวข้อหน้าตา)
  prepare/
    VideoRow.tsx  AnalysisProgress.tsx  ResultPeek.tsx
  outline/
    BriefPanel.tsx  BeatCard.tsx  BeatList.tsx (ลาก)  UnusedParts.tsx (คงเดิม)
  edit/
    BeatSidebar.tsx      รายการบีต + ป้ายนับ + สรุป
    BeatPanel.tsx        หัวเรื่อง + แท็บ
    SpeechTab.tsx        (จาก CutRows.tsx)
    HighlightTab.tsx     (จาก HighlightGroups.tsx)
    LookPopover.tsx      (แยกจาก HighlightGroups.tsx)
    SubtitleTab.tsx
    FlairTab.tsx         (รวม SoundCues + ZoomCues + InsertCues)
    ClipSettingsSheet.tsx (รวม cut rules + SubtitleSection + HighlightSection + FlairSection)
    WriteBar.tsx         ปุ่มเขียน + แผ่นยืนยัน + toast
    byBeat.ts            แยก cues/zooms/inserts/slots/pieces ตามบีต (ฟังก์ชันบริสุทธิ์)
  theme.ts               อ่านค่าหน้าตาจาก settings แล้วตั้ง data-theme บน <html>
  styles/
    tokens.css  base.css  shell.css  screens.css  edit.css
```

ชิ้นส่วนใน `ui/` ไม่รู้จัก API ของแอปเลย รับ props ล้วน ทดสอบแยกได้ · ชิ้นส่วนใน `edit/` รับข้อมูลที่คำนวณแล้วเป็น props ไม่เรียก API เอง (ยกเว้น EditScreen ที่ถือ state ทั้งหมดเหมือนเดิม)

`byBeat.ts` เป็นหัวใจของการจัดของเข้าบีต: รับ `HighlightPreview` + `CutPlan` แล้วคืน `Map<beatId, { groups, cues, zooms, inserts, slots, pieces }>` — ฟังก์ชันบริสุทธิ์ ทดสอบง่าย

## 5. สิ่งที่ต้องแก้ฝั่ง main process

มีแค่สองอย่าง:

1. **`beatId` ในมุมมองของลูกเล่น** — `HighlightPreview` ปัจจุบันให้ `slots`, `cues`, `zooms`, `pieces`, `inserts` เป็นรายการแบน ผูกกับ anchor เท่านั้น renderer หาบีตเองได้ (จับคู่ `{videoId, sourceUs}` กับชิ้นใน `CutPlan` และ `groupId` กับกลุ่ม) แต่ลอจิกนั้นควรอยู่ที่เดียวกับที่สร้างมัน จึง **เพิ่มฟิลด์ `beatId: string` ให้ทั้งห้ารายการ** ใน `highlights.ts` — เติมตอนสร้าง view ไม่เปลี่ยนวิธีคำนวณหรือรูปแบบที่เก็บลง settings
2. **ค่าหน้าตา** — เพิ่ม `appearance: "system" | "light" | "dark"` ใน settings (ค่าเริ่มต้น `system`), ใน `SettingsView`, และใน `SettingsPatch` · main ใช้ค่านี้ตั้ง `nativeTheme.themeSource` ด้วย เพื่อให้ขอบหน้าต่างและ vibrancy ตรงกับในแอป

ไม่แตะ: ตัวเขียน draft, prompt, cut compiler, pipeline, license, รูปแบบข้อมูลที่เก็บลงดิสก์

## 6. การทดสอบ

- **`ui/`** — เทสต์ต่อชิ้น: render, คลิก, คีย์บอร์ด (Esc ปิด Sheet/Popover, ลูกศรใน Segmented/Tabs), aria
- **`byBeat.ts`** — เทสต์บริสุทธิ์: จุดของบีตไหนไปบีตนั้น, จุดที่หาบีตไม่เจอถูกทิ้งและนับ, ลำดับตามเวลา
- **แต่ละ screen** — เทสต์ระดับพฤติกรรมด้วย `fakeApi` เดิม: เดินครบเส้นทางของระยะนั้น, สถานะว่าง/กำลังโหลด/ผิดพลาด, ปุ่มที่ถูกปิดกั้นตอน CapCut เปิด
- **ลากเรียงบีต** — เทสต์ด้วย event `dragstart/dragover/drop` และด้วยปุ่ม ↑↓ ให้ได้ลำดับเดียวกัน
- **ธีม** — เทสต์ว่าเลือกมืดแล้ว `<html data-theme="dark">` และเรียก `updateSettings` ถูก
- เทสต์เดิมของ `TimelineScreen`, `AnalyzeScreen`, `OutlineScreen`, `SettingsScreen` ต้องเขียนใหม่ตามโครงใหม่ — คงข้อความ i18n เดิมไว้ให้มากที่สุดเพื่อให้เทียบเคียงได้
- ยังใช้ TDD + mutation check เหมือนทุก milestone ที่ผ่านมา

## 7. ความเสี่ยง

- **งานใหญ่กว่าที่เห็น**: renderer เกือบทั้งหมดถูกจัดใหม่ และเทสต์ renderer ~1,500 บรรทัดต้องเขียนตาม · บรรเทาด้วยการทำทีละระยะ (เปลือก → เตรียม → โครงเรื่อง → ตัดต่อ → ตั้งค่า) แต่ละระยะจบแล้วแอปยังรันได้
- **ไม่มีแถบเวลาและไม่มีพรีวิว** แปลว่าผู้ใช้ยังต้องเปิด CapCut เพื่อดูผลจริง — เป็นการแลกที่ผู้ใช้เลือกเอง ถ้าอยากได้ทีหลังค่อยเพิ่มเป็น milestone แยก
- **การลาก** ไม่มี library ถ้าพฤติกรรมไม่ดีพอบน trackpad อาจต้องเพิ่ม `@dnd-kit` ทีหลัง
- **ป้ายนับในบีต** จะถูกต้องก็ต่อเมื่อ `beatId` จากข้อ 5.1 ถูก ถ้า anchor หาบีตไม่เจอ (เช่น anchor ท้ายคลิป) ต้องมีที่อยู่ให้มัน — ใช้บีตสุดท้ายและเขียนเทสต์ครอบ
