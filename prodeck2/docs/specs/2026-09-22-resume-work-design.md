# M16 · กลับมาทำงานต่อ: ข้ามการวิเคราะห์ซ้ำ และป้ายสถานะในรายการโปรเจกต์ — design

วันที่ 2026-09-22 · ต่อจาก M11 (โครงหน้าจอ 3 ระยะ)

## 1. ปัญหาจากการใช้จริง

ผู้ใช้ถามว่า "เวลาดูอันที่เคยวิเคราะห์เขียนโครงแล้ว ต้องทำใหม่หมด ไม่เก็บประวัติไว้หรอ"

ของถูกเก็บครบอยู่แล้ว — `transcripts/`, `insights/`, `media-looks/`, `loudness/`, `subtitle-polish/`
และ `outlines/<sha256(folder)>.json` ซึ่งเก็บทั้ง brief, โครงเรื่อง, `confirmed`, `cutDecisions`,
`highlights` และ `flair` — แต่ **ทางเดินของผู้ใช้ไม่ถูกเก็บ**

- `journey` ใน [`App.tsx`](../../apps/desktop/src/renderer/src/App.tsx) เป็น React state ล้วน ปิดแอปแล้วหาย
- `analysisState()` อยู่ใน memory ของ main process รอดแค่ตอนสลับหน้า ไม่รอดปิดแอป

ผลคือเปิดโปรเจกต์เดิมแล้ว**ต้องกด "เริ่มวิเคราะห์" ใหม่ทุกครั้ง**เพื่อให้ปุ่ม "ไปโครงเรื่อง" โผล่ ทั้งที่ผลทุกอย่างอยู่ในแคช
(วิ่งจากแคช ไม่ยิง API ไม่เสียเงิน แต่ผู้ใช้ไม่รู้ และยังต้องรอ) · และหน้ารายการโปรเจกต์ไม่บอกว่าอันไหนเคยทำถึงไหน

## 2. สิ่งที่ผู้ใช้เลือก

เอาสองข้อ — (1) ข้ามขั้นวิเคราะห์เมื่อแคชครบ (2) ป้ายบอกสถานะในหน้ารายการ ·
ข้อ 3 (เก็บประวัติเวอร์ชันโครงเรื่อง) ยังไม่เอา

## 3. ข้ามขั้นวิเคราะห์ (`footage.ts`, `PrepareScreen.tsx`)

`loadFootage` สร้างคีย์แคชของทั้ง ASR และ vision อยู่แล้ว · แยกออกมาเป็น `footageKeys(deps)` แล้วเพิ่ม

```ts
export async function analysedVideos(deps: FootageDeps, folder: string): Promise<string[]>
```

คืน id ของวิดีโอที่มี**ทั้ง** transcript และ insight ในแคชตามการตั้งค่าปัจจุบัน · วิดีโอเงียบก็มี transcript
(`silence()`) จึงนับได้เหมือนกัน · เปลี่ยนเครื่องถอดเสียง โมเดล ภาษา หรือไฟล์ต้นทาง = คีย์เปลี่ยน = ไม่นับว่าวิเคราะห์แล้ว
(กฎเดิมของ `MediaCache` ที่รวม path, ขนาด และเวลาแก้ไฟล์)

API ใหม่ `analysedVideos(folder)` · หน้าเตรียม:

- ปุ่มหลักเป็น **"ไปโครงเรื่อง"** เมื่อวิดีโอที่ติ๊ก**ทุกตัว**อยู่ในชุดที่วิเคราะห์แล้ว มิฉะนั้นเป็น "เริ่มวิเคราะห์" ตามเดิม ·
  ติ๊กวิดีโอที่ยังไม่ได้วิเคราะห์เพิ่ม ปุ่มก็กลับเป็น "เริ่มวิเคราะห์" เอง (การวิเคราะห์ที่วิ่งจะใช้แคชของตัวที่มีอยู่แล้ว)
- ไม่ติด gate ของ CapCut: การไปหน้าโครงเรื่องไม่แตะ draft
- แถววิดีโอที่มีผลแล้ว**ถอยเป็นสีเทา** (ชื่อ ความยาว และช่องติ๊กเป็นสีรอง) พร้อมป้าย "วิเคราะห์แล้ว" ·
  แถวที่ยังไม่ได้อ่านคงช่องติ๊กสีเน้นเหมือนเดิม จึงเห็นทันทีว่าเหลืออะไรให้ทำ · สีเทา = อ่านแล้ว **ไม่ใช่ล็อก**:
  ยังติ๊กออกเพื่อไม่ให้เข้าเรื่องได้ · พอเริ่มวิเคราะห์ สีเทาหายไปเพราะแถวกำลังบอกความคืบหน้าของตัวเอง ·
  ไฟล์ที่หายไปแล้วไม่เป็นสีเทาและไม่ขึ้นป้าย ต่อให้ยังมีผลค้างในแคช

## 4. ป้ายสถานะในรายการ (`progress.ts` ใหม่, `api.ts`, `ProjectsScreen.tsx`)

ตรวจแคชจริงของทุกโปรเจกต์ในรายการแพงเกินไป (ต้องอ่าน draft ของแต่ละอันเพื่อรู้ว่ามีวิดีโออะไร) ·
ใช้ของที่เราเขียนเองแทน

```ts
export interface ProjectProgress { folder: string; analysedAt: number; videoIds: string[] }
export interface ProjectStage { stage: "analysed" | "outline" | "confirmed"; at: number }
```

- `ProgressStore` เก็บที่ `progress/<sha256(folder)>.json` · **เขียนที่เดียว**: ตอน analysis run จบแบบ `done`
  (ยกเลิกหรือพังไม่เขียน) · `all()` อ่านทั้งโฟลเดอร์ ซึ่งมีเฉพาะโปรเจกต์ที่เคยทำ จึงเล็ก
- `stagesOf(progress, outlines)` เลือกสถานะไกลสุดต่อโปรเจกต์: `confirmed` > `outline` > `analysed` ·
  เวลาที่แสดงคือ `updatedAt` ของโครงเรื่อง หรือ `analysedAt`
- `listProjects()` คืน `stages: Record<folder, ProjectStage>` มาพร้อมรายการ จะได้ไม่ต้องยิงสองรอบ
- การ์ดในหน้ารายการขึ้นป้ายชื่อระยะ + วันที่

ที่ยอมรับ: โปรเจกต์ที่วิเคราะห์ไว้**ก่อน**รุ่นนี้ยังไม่มีไฟล์ progress จึงไม่มีป้าย "วิเคราะห์แล้ว" จนกว่าจะวิเคราะห์อีกครั้ง ·
แต่ถ้าเคยวางโครงเรื่องไว้ ป้ายโครงเรื่องขึ้นทันทีเพราะอ่านจาก `outlines/` ที่มีอยู่แล้ว

## 5. ไม่อยู่ในขอบเขต
